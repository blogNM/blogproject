# Feature Specification: 메인 관리자와 제재

**Feature Branch**: `005-admin-moderation`

**Created**: 2026-10-07

**Status**: Draft (요구사항 확정, 구현 계획 전)

**Input**: 요구사항분석서 1편 2장 권한 표, 3.5 메인 관리자(ADM-01~07), 3.7 제재 권한, 4.1 SEC-09, 4.4 가림 표시, 4.5 데이터 보관

## 범위

메인 관리자는 관리자 페이지에서 모든 블로그와 블로그장을 관리하고, 회원은 검색·조회만 합니다. 회원 정지와 강제 퇴장은 블로그 단위로 블로그장이 합니다(→ [002 BLG-13](../002-blog-management/spec.md)). 관리자가 한 조치는 모두 기록으로 남깁니다.

- 포함: 회원 검색·조회, 블로그 관리(숨김·강제 폐쇄), 글·댓글 숨김·삭제, 블로그·블로그장 신고 처리, 통계, 관리자 활동 기록, 블로그장 경고·강퇴
- 제외: 회원 정지·강제 탈퇴(메인 관리자는 하지 않음, D-44), 멤버 제재(블로그장)

## 제재 권한 비교 (3.7)

| 구분 | 메인 관리자 | 블로그장 (멤버 관리 권한을 받은 부블로그장 포함) |
|---|---|---|
| 제재 대상 | 블로그장, 블로그 | 자기 블로그의 멤버 |
| 신고 처리 | 블로그 자체, 블로그장과 블로그장의 글·댓글, 메인 프로필에서 한 회원 신고 (ADM-04, D-85) | 블로그 안의 회원·글·댓글 신고 (BLG-13) |
| 경고 | 블로그장 경고. 3번이면 블로그장 권한 박탈 (ADM-07) | 멤버 경고 |
| 정지 | 없음 (D-44) | 멤버 정지. 정지 기간 동안 그 블로그에만 못 들어감 |
| 내보내기 | 블로그장 강퇴(권한 박탈). 박탈된 사람은 일반 멤버로 남음 | 멤버 강제 퇴장. 정지 3번이면 처리, 블랙리스트 등록 (BLG-11) |
| 폐쇄 | 블로그 강제 폐쇄 (7일 유예, 블로그장이 철회 가능, D-86) | 자기 블로그 폐쇄 (7일 유예, 철회 가능) |
| 글 삭제 | 모든 블로그의 글 | 자기 블로그의 글. 둘 다 남의 글 수정은 불가 |

정지 기간(공통): 3일, 14일, 30일, 영구. 기간이 끝나거나 정지를 준 사람이 해제하면 풀린다 (D-57).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 블로그장 경고와 강퇴 (Priority: P1)

메인 관리자가 문제 있는 블로그장에게 경고를 주고, 3번 쌓이거나 바로 강퇴하면 블로그장 권한을 박탈한다.

**Why this priority**: 메인 관리자가 블로그 운영 질서를 지키는 주된 수단이다.

**Independent Test**: 경고 3번째에 권한이 박탈되고, 부블로그장이 있으면 가장 먼저 부블로그장이 된 사람에게 넘어가며, 없으면 7일 뒤 04:00 폐쇄 예정이 되면 통과.

**Acceptance Scenarios**:

1. **Given** 경고 2번인 블로그장, **When** 관리자가 세 번째 경고를 주면, **Then** 블로그장 권한이 박탈되고 블로그장에게 알림이 간다.
2. **Given** 부블로그장이 2명, **When** 블로그장이 강퇴되면, **Then** 가장 먼저 부블로그장이 된 사람이 블로그장이 된다.
3. **Given** 부블로그장이 없음, **When** 블로그장이 강퇴되면, **Then** 7일 뒤 04:00 폐쇄 예정이 되고 "블로그장 권한 박탈로 인한 폐쇄 조치" 공지와 함께 멤버·구독자에게 BLG-09와 같은 폐쇄 알림이 간다.
4. **Given** 권한을 박탈당한 블로그장, **When** 처리가 끝나면, **Then** 그 블로그의 일반 멤버로 남고, 새 블로그장이 유지·정지·강제 퇴장을 판단한다 (D-54).

---

### User Story 2 - 신고 처리 (Priority: P1)

메인 관리자가 블로그 자체나 블로그장에 대한 신고를 확인하고 조치한다.

**Why this priority**: 블로그장을 제재할 수 있는 사람은 메인 관리자뿐이다.

**Independent Test**: 블로그 신고가 관리자 화면에만 보이고, 처리 결과가 신고자에게 알림으로 가면 통과.

**Acceptance Scenarios**:

1. **Given** 블로그·블로그장 신고, **When** 관리자가 처리하면, **Then** 문제 없음·블로그장 경고·블로그장 강퇴·블로그 폐쇄 중 하나로 처리되고 신고자에게 알림이 간다.
2. **Given** 블로그 안의 글 신고, **When** 관리자 화면을 보면, **Then** 보이지 않는다. 그 블로그의 블로그장이 처리한다.

---

### User Story 3 - 블로그·글 관리 (Priority: P2)

메인 관리자가 블로그를 검색하고, 문제 블로그를 숨기거나 강제 폐쇄하고, 어느 블로그의 글이든 숨기거나 삭제한다.

**Why this priority**: 신고 처리 결과를 실제로 반영하는 수단이다.

**Independent Test**: 관리자가 글을 삭제하면 작성자에게 알림이 가고, 관리자는 그 글을 수정할 수 없으면 통과.

**Acceptance Scenarios**:

1. **Given** 블로그 검색, **When** 관리자가 보면, **Then** 블로그장·멤버 수·글 수가 보인다.
2. **Given** 아무 블로그의 글, **When** 관리자가 삭제하면, **Then** 작성자에게 "내 글 삭제됨" 알림이 간다. 수정은 할 수 없다.
3. **Given** 삭제된 글, **When** 30일 안에 관리자가 복구하면, **Then** 다시 보인다.

---

### User Story 4 - 회원 조회와 개인정보 열람 기록 (Priority: P2)

메인 관리자가 회원을 검색해 상세 정보를 보되, 개인정보는 기본으로 가려져 있고 "전체 보기"를 누른 기록이 남는다.

**Why this priority**: 관리자 권한 남용을 막는 장치다.

**Independent Test**: 관리자 회원 상세에서 이메일·전화번호가 가려져 있고, "전체 보기"를 누르면 활동 기록에 남으면 통과.

**Acceptance Scenarios**:

1. **Given** 회원 상세, **When** 관리자가 열면, **Then** 이메일·이름·닉네임·전화번호가 기본으로 가려져 있다.
2. **Given** 회원 상세, **When** "전체 보기"를 누르면, **Then** 원래 값이 보이고 누가 언제 눌렀는지 기록된다 (ADM-06).
3. **Given** 회원 상세, **When** 관리자가 회원을 정지하려 하면, **Then** 그런 기능이 없다 (D-44).

---

### User Story 5 - 통계와 활동 기록 (Priority: P3)

메인 관리자가 서비스 현황을 보고, 관리자 조치 기록을 확인한다.

**Why this priority**: 운영 판단과 분쟁 확인에 쓰인다.

**Independent Test**: 회원 수·블로그 수·일별 가입·글 수가 보이고, 경고·강퇴·삭제·폐쇄 조치가 누가 언제 했는지 남으면 통과.

**Acceptance Scenarios**:

1. **Given** 통계 화면, **When** 열면, **Then** 회원 수, 블로그 수, 일별 가입 수, 일별 글 수가 보인다.
2. **Given** 관리자 조치, **When** 경고·강퇴·삭제·폐쇄·숨김을 하면, **Then** 누가 언제 무엇을 했는지 기록되고 1년 보관된다 (D-60).

### Edge Cases

- 블로그장 강퇴로 폐쇄 예정이 된 블로그도 7일 동안 평소처럼 운영된다 (D-67).
- 경고 3번 누적은 그 블로그에서의 블로그장 경고만 세고, 1년이 지난 경고는 뺀다 (D-87).
- 메인 관리자는 회원 계정과 분리된 관리자 계정을 쓰고 블로그 활동(블로그 생성·참여·글쓰기·팔로우·댓글·좋아요)을 하지 않는다. 참여 승인·멤버 강퇴도 하지 않는다 (D-84).

## Requirements *(mandatory)*

### Functional Requirements

- **ADM-01 회원 관리** (상): 전체 회원을 검색하고 상세 정보를 본다. 회원 정지·강제 퇴장은 블로그장이 한다(BLG-13). 메인 관리자는 블로그장 강퇴(ADM-07)와 블로그 폐쇄(ADM-02)만. 블로그장이 강퇴되면 부블로그장에게 자동 위임(여러 명이면 가장 먼저 된 사람), 없으면 7일 뒤 04:00 폐쇄 (D-17, D-44).
- **ADM-02 블로그 관리** (상): 전체 블로그를 검색하고 블로그장·멤버 수·글 수를 본다. 블로그를 숨기거나 강제 폐쇄한다. 강제 폐쇄는 누른 날짜 + 7일 04:00에 닫히고 블로그장이 철회할 수 있다 (D-86).
- **ADM-03 게시글·댓글 관리** (중): 어느 블로그의 글이든 숨기거나 삭제한다.
- **ADM-04 신고 처리** (중, SOC-06): 블로그 자체·블로그장 신고를 처리한다. 결과는 문제 없음, 블로그장 경고, 블로그장 강퇴(ADM-07), 블로그 폐쇄 중 하나. 결과는 신고자에게 알림 (D-38, D-45).
- **ADM-05 통계** (하): 회원 수, 블로그 수, 일별 가입·글 수.
- **ADM-06 관리자 활동 기록** (중, SEC-09): 경고, 강퇴, 삭제, 폐쇄 같은 조치와 개인정보 "전체 보기"를 누가 언제 했는지 남긴다. 1년 보관.
- **ADM-07 블로그장 경고·강퇴** (중, ADM-04, BLG-09): 경고 3번 또는 바로 강퇴하면 권한 박탈. 부블로그장(가장 먼저 된 사람)에게 이전, 없으면 7일 유예 후 폐쇄 + "블로그장 권한 박탈로 인한 폐쇄 조치" 공지 + 멤버·구독자 폐쇄 알림. 박탈된 사람은 일반 멤버로 남음 (D-30, D-54).

### 보안 요구사항

- **SEC-09**: 관리자 계정은 일반 회원과 분리하고 활동을 기록한다. 관리자는 블로그 활동을 하지 않는다 (D-84).
- **SEC-11**: 관리자 페이지는 주소 단위로 관리자만 접근하게 한다.
- 개인정보는 기본으로 가리고 "전체 보기"를 누른 기록을 남긴다 (4.4).

### Key Entities

- **관리자 계정**: 일반 회원과 분리된 계정 (SEC-09).
- **관리자 활동 기록**: 관리자, 조치 종류(경고·강퇴·삭제·숨김·폐쇄·복구·전체 보기), 대상, 사유, 시각. 1년 보관.
- **블로그장 경고**: 블로그, 대상 블로그장, 사유, 신고 연결, 시각. 1년 보관.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자 조치는 한 건도 빠짐없이 활동 기록에 남는다.
- **SC-002**: 관리자 화면에서 회원 개인정보 원문은 "전체 보기" 기록 없이 보이지 않는다.
- **SC-003**: 블로그장이 강퇴된 블로그는 블로그장 없는 상태로 남지 않는다 (자동 위임 또는 폐쇄 예정).
- **SC-004**: 관리자가 남의 글을 수정하는 요청은 거절된다.

## Clarifications

### 결정 기록에서 옮김 (2026-10-02 ~ 2026-10-06)

- Q: 메인 관리자가 회원을 정지하나? → A: 하지 않음. 블로그장 강퇴와 블로그 폐쇄만 (D-44). 멤버 제재는 블로그 단위로 블로그장이 (D-43)
- Q: 신고는 누가 처리하나? → A: 블로그 안은 블로그장, 블로그·블로그장은 메인 관리자 (D-45). 결과는 문제 없음·경고·정지·강제 퇴장 등으로 정해 둠 (D-38)
- Q: 블로그장 제재 방식은? → A: 경고 3회 누적 시 권한 박탈, 부블로그장에게 이전 또는 7일 유예 후 폐쇄 (D-30). 강퇴 시 자동 위임 규칙 (D-17)
- Q: 박탈된 블로그장은? → A: 일반 멤버로 남고 새 블로그장이 판단 (D-54)
- Q: 정지 기간 선택지는? → A: 관리자·블로그장 공통 3일·14일·30일·영구 (D-57)
- Q: 운영 기록 보관은? → A: 30일이 아니라 1년 (D-60)
- Q: 관리자가 글을 수정할 수 있나? → A: 불가, 삭제만 (D-07)

### 2026-10-07 팀 결정 (김채림)

- Q: 관리자 계정은? → A: 회원과 분리된 계정, 블로그 활동을 하지 않음. 2장 권한 표의 관리자 칸 중 블로그 생성·참여·글쓰기·팔로우·댓글·좋아요·참여 승인·멤버 강퇴를 X로 고침 (D-84)
- Q: 신고 접수처는? → A: 블로그장·블로그장의 글·댓글·블로그 자체·메인 프로필 신고는 메인 관리자 (D-85)
- Q: 강제 폐쇄 시점은? → A: 누른 날짜 + 7일 04:00, 철회는 블로그장 (D-86)
- Q: 블로그장 경고 3번은 어떻게 세나? → A: 블로그별로, 1년 지난 경고는 뺌 (D-87)

- 글·댓글 숨김과 되살리기 (6단계 기본값, 확인 대기): 숨긴 글은 글쓴이에게도 안 보이고 관리자가 풀 수 있음. 숨기거나 지운 댓글은 "삭제된 댓글"로 보임. 관리자가 지운 글만 30일 안에 되살릴 수 있음(글쓴이·블로그장이 지운 글은 안 됨)
- 신고 대상이 블로그와 관계없을 때(메인 프로필 신고): 관리자는 "문제 없음"으로만 닫음. 관리자는 회원 정지·강퇴를 하지 않기 때문(ADM-01). 6단계 기본값, 확인 대기

- Q: 신고를 처리할 때 제재 사유를 나눠 볼 수 있나? → A: 제재 사유 항목 8가지 중 하나를 고르고 처리한 신고·제재 기록을 항목별로 나눠 봄. 항목 목록은 기본값, 확인 대기 (D-95, 2026-10-08 김채림 요청)
