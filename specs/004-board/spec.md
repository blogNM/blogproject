# Feature Specification: 게시판 (글·댓글·검색·피드)

**Feature Branch**: `004-board`

**Created**: 2026-10-07

**Status**: Draft (요구사항 확정, 구현 계획 전)

**Input**: 요구사항분석서 1편 3.4 게시판(BRD-01~11), 4.2 성능·사용성, 7장 화면 방식·에디터·이미지 저장·조회수 / 2편 6.1 검색, 6.2 SNS 공유, 6.3 파일 업로드, 6.4 태그, 6.6 글·댓글 상세, 6.7 조회수

## 범위

게시판은 공통 모듈로 한 번 만들고, 메인(공지사항)과 모든 개별 블로그가 같이 씁니다.

- 공통 모듈: BRD-01~07, BRD-11 (글, 목록, 카테고리, 태그, 이미지, 댓글·좋아요, 공유, 조회수)
- 메인 전용: BRD-08 통합 검색, BRD-09 메인 피드, BRD-10 공지사항
- 제외: 서버 임시저장, 검색 자동완성, 목록 썸네일 생성, SNS 공유 버튼(링크 복사 외) — 모두 2차

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글 쓰고 읽기 (Priority: P1)

멤버가 참여한 블로그에서 마크다운으로 글을 쓰고, 누구나(공개 범위 안에서) 글을 읽는다.

**Why this priority**: 블로그의 존재 이유다.

**Independent Test**: 멤버가 Toast UI Editor로 쓴 글이 저장되고, 글 상세에서 본문이 안전하게 HTML로 보이면 통과.

**Acceptance Scenarios**:

1. **Given** 그 블로그의 멤버가 아닌 회원, **When** 글을 쓰려 하면, **Then** 거절된다.
2. **Given** 본문에 `<script>`나 `onerror=` 같은 위험한 태그·속성이 든 마크다운, **When** 글을 보면, **Then** 서버가 jsoup으로 걸러낸 HTML만 내려가 스크립트가 실행되지 않는다.
3. **Given** 글 상세, **When** 제목·닉네임·태그·댓글을 표시하면, **Then** 모두 `textContent`로 넣는다. `innerHTML`은 본문에만 쓴다.
4. **Given** 글쓰기 중, **When** 브라우저가 닫혔다 다시 열리면, **Then** 브라우저에 자동 저장된 내용이 남아 있다 (1차는 브라우저에만).
5. **Given** 제목 31자, 본문 1001자, **When** 저장하면, **Then** 거절된다.
6. **Given** 내가 쓴 글, **When** 삭제를 누르면, **Then** "글을 정말 삭제하시겠습니까?" 확인 창이 뜬다.

---

### User Story 2 - 글 수정·삭제 권한 (Priority: P1)

작성자만 글을 고치고, 삭제는 작성자·블로그장(자기 블로그 글)·메인 관리자가 한다.

**Why this priority**: 블로그별 역할 확인(SEC-07)이 가장 많이 걸리는 곳이다.

**Independent Test**: 블로그장과 관리자가 남의 글을 수정하는 요청이 거절되고, 삭제는 되며 작성자에게 알림이 가면 통과.

**Acceptance Scenarios**:

1. **Given** 블로그장, **When** 자기 블로그의 다른 멤버 글을 수정하려 하면, **Then** 거절된다. 삭제는 되고 작성자에게 "내 글 삭제됨" 알림이 간다 (D-58).
2. **Given** A 블로그의 블로그장, **When** B 블로그의 글을 삭제하려 하면, **Then** 거절된다.
3. **Given** 메인 관리자, **When** 아무 블로그의 글을 수정하려 하면, **Then** 거절된다. 삭제는 된다 (D-07).
4. **Given** 삭제된 글, **When** 30일 안이면, **Then** 화면에는 안 보이지만 관리자가 복구할 수 있다. 30일 뒤 완전히 삭제된다.

---

### User Story 3 - 목록·카테고리·태그로 둘러보기 (Priority: P2)

방문자가 글 목록을 최신순으로 넘겨 보고, 카테고리나 태그로 모아 본다.

**Why this priority**: 글을 찾아 읽는 기본 동선이다.

**Independent Test**: 목록이 번호 페이지로 10개씩 나오고 20·30개로 바꿀 수 있으며, 태그를 누르면 같은 태그 글만 나오면 통과.

**Acceptance Scenarios**:

1. **Given** 글 목록, **When** 처음 열면, **Then** 최신순 10개가 번호 페이지로 보인다. 10·20·30개 중 고를 수 있다 (D-06, D-76).
2. **Given** 태그 `#맛집 `, **When** 저장하면, **Then** 앞의 #과 앞뒤 공백을 지워 `맛집`으로 저장된다. 가운데 공백은 `_`로 바뀐다.
3. **Given** 태그 `Java`와 `java`, **When** 저장하면, **Then** 소문자 `java` 하나로 합쳐진다.
4. **Given** 글 하나에 태그 11개, **When** 저장하면, **Then** 거절된다.
5. **Given** 글 목록, **When** 글 제목에 마우스를 올리면, **Then** 글의 사진이 보인다 (원본을 CSS로 줄여 표시).

---

### User Story 4 - 이미지 올리기 (Priority: P2)

멤버가 글에 이미지를 올린다.

**Why this priority**: 블로그 글의 기본 요소이며, 업로드는 보안 위험이 큰 곳이다.

**Independent Test**: 확장자만 `.jpg`로 바꾼 실행 파일이 거절되고, 정상 사진은 GPS 정보가 지워진 채 UUID 이름으로 저장되면 통과.

**Acceptance Scenarios**:

1. **Given** `.svg`, 동영상, pdf·hwp, 압축 파일, **When** 올리면, **Then** 거절된다.
2. **Given** 확장자는 `.png`인데 파일 앞부분(시그니처)이 PNG가 아님, **When** 올리면, **Then** 거절된다.
3. **Given** 3MB가 넘는 사진, **When** 올리면, **Then** 거절된다. 글 하나에 10장, 한 번에 10MB까지.
4. **Given** GPS 정보가 든 사진, **When** 올리면, **Then** EXIF를 지우고 UUID 이름으로 저장하며 원래 이름은 DB에만 남긴다.

---

### User Story 5 - 댓글과 좋아요 (Priority: P2)

회원이 공개 글이나 참여한 블로그의 글에 댓글·대댓글을 달고 좋아요를 누른다.

**Why this priority**: 블로그 안의 소통 수단이다.

**Independent Test**: 대댓글이 1단계까지만 달리고 앞에 `@닉네임`이 붙으며, 답글이 있는 댓글을 지우면 "삭제된 댓글입니다"로 남으면 통과.

**Acceptance Scenarios**:

1. **Given** 대댓글, **When** 거기에 다시 답글을 달려 하면, **Then** 대댓글 깊이는 1단계로 유지되고 답글 앞에 `@닉네임`이 표시된다 (D-78).
2. **Given** 답글이 있는 댓글, **When** 삭제하면, **Then** "삭제된 댓글입니다"로 표시되고 답글은 남는다.
3. **Given** 수정한 댓글, **When** 보면, **Then** "수정됨"이 표시된다.
4. **Given** 이미 좋아요를 누른 글, **When** 다시 누르면, **Then** 좋아요가 취소된다.
5. **Given** 501자 댓글, **When** 저장하면, **Then** 거절된다.

---

### User Story 6 - 통합 검색 (Priority: P2)

방문자가 메인에서 블로그와 공개 글을 한 번에 검색한다.

**Why this priority**: 메인의 핵심 진입 경로다.

**Independent Test**: 2글자 검색어로 블로그 이름·글 제목·태그·닉네임 결과가 분류바로 나뉘어 나오고, 비공개 블로그 글은 나오지 않으면 통과.

**Acceptance Scenarios**:

1. **Given** 1글자나 21자 검색어, 공백·특수문자만 있는 검색어, **When** 검색하면, **Then** 막힌다.
2. **Given** 검색 결과, **When** 정렬을 바꾸면, **Then** 관련도순(기본)·최신순·인기순 중에서 고른다.
3. **Given** 비공개 블로그의 글, 숨김·삭제 글, 내가 차단한 회원의 글, **When** 검색하면, **Then** 결과에 나오지 않는다.
4. **Given** 결과 없음, **When** 검색하면, **Then** "검색 결과가 없습니다"가 보인다.
5. **Given** 로그인한 회원, **When** 검색창을 누르면, **Then** 본인의 최근 검색어가 최대 10개 보이고, 하나씩 또는 전체를 지울 수 있다.

---

### User Story 7 - 메인 피드와 공지 (Priority: P2)

메인에서 최신·인기 공개 글, 팔로우한 회원의 새 글, 구독한 블로그의 새 글을 탭으로 나눠 본다.

**Why this priority**: 메인 화면의 첫인상이다.

**Independent Test**: 팔로우 탭과 구독 탭이 따로 보이고, 글이 삭제되거나 블로그가 비공개로 바뀌면 다음 조회에서 바로 빠지면 통과.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 메인 피드를 보면, **Then** 팔로우 탭과 구독 탭이 나뉘어 있다 (D-65).
2. **Given** 피드에 있던 글이 삭제됨, **When** 피드를 다시 보면, **Then** 빠져 있다 (볼 때마다 모아오기, D-73).
3. **Given** 메인 관리자, **When** 공지를 올리면, **Then** 메인 공지사항에 보이고 전체 회원에게 알림이 간다.

---

### User Story 8 - 공유와 조회수 (Priority: P3)

방문자가 글 링크를 복사해 공유하고, 글을 열면 조회수가 오른다.

**Why this priority**: 외부 유입과 인기 지표에 쓰인다.

**Independent Test**: 글 상세 주소를 카카오톡 미리보기로 열면 제목·요약·이미지가 보이고, 같은 사람이 같은 날 여러 번 열어도 조회수가 1만 오르면 통과.

**Acceptance Scenarios**:

1. **Given** 글 상세 주소, **When** 카톡·X가 가져가면, **Then** 서버가 채운 og 태그(og:title, og:description, og:image)가 있다. 이미지는 글의 첫 이미지, 없으면 블로그 대표 이미지 (D-59).
2. **Given** 공유 미리보기, **When** 보이면, **Then** 주소 → 제목 → 이미지 순서다.
3. **Given** 같은 사람이 같은 날 같은 글을 여러 번 열거나 새로고침, **When** 조회수를 세면, **Then** 1번만 센다 (DB 조회 기록 테이블, D-77).

### Edge Cases

- 일부 공개 블로그의 글은 공유 링크로 들어온 사람만 보며, 통합 검색과 피드에는 나오지 않는다.
- 폐쇄 예정 7일 동안에도 글쓰기·댓글은 평소처럼 된다 (D-67).
- 떠나거나 강퇴된 멤버의 글은 작성자가 "탈퇴한 계정", 사이트를 탈퇴한 회원의 글은 "탈퇴한 회원"으로 표시된다.
- 공유 수는 집계하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **BRD-01 글 작성·조회·수정·삭제** (상, SEC-06·07): 제목과 본문(마크다운)으로 쓴다. 수정은 작성자만. 삭제는 작성자, 블로그장(자기 블로그 글), 관리자. 블로그장·관리자는 남의 글 수정 불가. 관리자·블로그장이 삭제하면 작성자에게 알림 (D-07, D-58).
- **BRD-02 목록·페이징** (상): 최신순, 번호 페이지, 10·20·30개 중 선택, 기본 10개 (D-06, D-76).
- **BRD-03 카테고리** (중): 글을 카테고리로 분류하고 카테고리별로 본다. 카테고리 관리는 블로그장.
- **BRD-04 태그** (중): 글에 태그를 달고, 누르면 같은 태그의 글을 본다.
- **BRD-05 이미지 첨부** (중, SEC-08): 아래 업로드 규칙.
- **BRD-06 댓글·좋아요** (중): 회원이 댓글을 달고 좋아요를 누른다. 대댓글 1단계 + `@닉네임` (D-78).
- **BRD-07 공유** (하): 1차는 링크 복사. 미리보기 이미지는 글의 첫 이미지를 줄여서, 없으면 블로그 대표 이미지를 줄여서. 주소 → 제목 → 이미지 순서 (D-59).
- **BRD-08 통합 검색** (중, 메인 전용): 블로그(이름·소개), 글 제목, 태그, 작성자 닉네임. 분류바로 대상 선택. 블로그·글 제목은 MySQL FULLTEXT + ngram, 태그·닉네임은 일치 검색. 10·20·30개 중 선택.
- **BRD-09 메인 피드** (상, 메인 전용): 최신·인기 공개 글, 팔로우한 회원의 새 글, 구독한 블로그의 새 글. 팔로우·구독은 탭으로 나눔 (D-65). 볼 때마다 모아옴 (D-73).
- **BRD-10 공지사항** (하, 메인 전용): 메인 관리자가 전체 회원에게 올린다.
- **BRD-11 조회수** (하): 비회원·회원·블로그장 모두 글을 열면 센다. 같은 사람이 같은 날 같은 글을 보면 1번만. DB 조회 기록 테이블 (D-77).

### 글·댓글 규칙 (6.6)

| 항목 | 규칙 |
|---|---|
| 제목 | 1~30자 |
| 본문 | 최대 1000자 |
| 에디터 | Toast UI Editor. 저장은 마크다운, 표시할 때 서버가 HTML로 바꾸고 jsoup으로 위험한 태그 제거 |
| 임시저장 | 1차는 브라우저에만 자동 저장 |
| 수정 표시 | 수정한 댓글에 "수정됨" 표시 |
| 댓글 | 1~500자 |
| 대댓글 | 1단계까지, 답글 앞에 `@닉네임` |
| 댓글 삭제 | 답글이 있으면 "삭제된 댓글입니다"로 남기고 답글 유지 |
| 글 삭제 | "글을 정말 삭제하시겠습니까?" 확인 |

### 태그 규칙 (6.4)

| 항목 | 규칙 |
|---|---|
| 개수 | 글 하나에 최대 10개 |
| 길이 | 1~20자 |
| 허용 문자 | 한글, 영문, 숫자, `_` |
| 입력 정리 | 앞의 `#`과 앞뒤 공백 제거, 가운데 공백은 `_` |
| 중복 | 한 글 안의 같은 태그는 하나로. 영문은 소문자로 저장 |
| 금칙어 | 만들지 않음 (D-88) |

### 업로드 규칙 (6.3, SEC-08)

| 항목 | 규칙 |
|---|---|
| 허용 형식 | jpg, jpeg, png, gif, webp |
| 제외 형식 | svg, 동영상, 문서(pdf, hwp 등), 압축 파일 |
| 크기·개수 | 글 이미지 장당 3MB, 글 하나에 10장, 한 번에 10MB. 프로필·블로그 대표 이미지 3MB 1장 |
| 검증 | 확장자, MIME 타입, 파일 시그니처 모두 |
| 저장 | UUID 이름, 원래 이름은 DB에만. 1차 서버 디스크, `FileStorage` 인터페이스로 분리 (D-75, SCL-02) |
| 위치 정보 | EXIF(GPS 등) 제거 |
| 썸네일 | 1차는 따로 만들지 않고 원본을 CSS로 줄여 표시 |

### 검색 규칙 (6.1)

| 항목 | 규칙 |
|---|---|
| 검색어 길이 | 2~20자 (ngram이 2글자 단위) |
| 정렬 | 관련도순(기본), 최신순, 인기순 |
| 결과에서 제외 | 비공개 블로그, 숨김·삭제 글, 내가 차단한 회원의 글 |
| 최근 검색어 | 본인만, 최대 10개, 하나씩·전체 삭제 |

### 화면 방식 (7장, D-66)

- 화면은 정적 HTML + JS. JS가 API로 데이터를 받아 채운다.
- 글 상세 주소만 서버가 HTML의 og 태그(제목·요약·이미지)를 채워서 내려준다. 카톡·X는 JS를 실행하지 않기 때문이다.
- 상태를 바꾸는 모든 요청은 공통 `api.js`에서 `X-XSRF-TOKEN` 헤더를 붙인다.

### Key Entities

- **글**: 블로그(메인 공지는 메인), 작성자, 카테고리, 제목, 본문 마크다운, 상태(정상·숨김·삭제), 삭제 시각, 작성·수정 시각.
- **카테고리**: 블로그, 이름.
- **태그 / 글 태그**: 태그 이름(소문자 정규화), 글 × 태그 고유(`uk_post_tags`).
- **첨부 이미지**: 글, 저장 이름(UUID), 원래 이름, 크기, 형식, 순서(첫 이미지 = 미리보기).
- **댓글**: 글, 작성자, 부모 댓글(1단계), 답글 대상 닉네임, 내용, 수정 여부, 삭제 여부.
- **좋아요**: 회원 × 글 고유.
- **조회 기록**: 글, 보는 사람 식별값, 날짜. (글, 식별값, 날짜) 고유.
- **최근 검색어**: 회원, 검색어, 검색 시각 (최대 10개).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 메인·목록·검색 결과가 1초 안에(늦어도 2초) 응답한다. 5초를 넘기면 중단하고 다시 시도하라고 안내한다 (D-48).
- **SC-002**: 글 본문을 제외한 어떤 사용자 입력도 `innerHTML`로 화면에 들어가지 않는다.
- **SC-003**: 확장자·MIME·시그니처 중 하나라도 맞지 않는 파일은 저장되지 않는다.
- **SC-004**: 같은 사람이 같은 날 같은 글을 몇 번 열어도 조회수는 1만 오른다.
- **SC-005**: 비공개 블로그와 차단한 회원의 글이 검색·피드에 한 건도 나오지 않는다.
- **SC-006**: PC와 모바일 화면 모두에서 글을 쓰고 읽을 수 있다 (4.2 반응형).

## Assumptions

- 좋아요는 회원당 1분에 30번, 같은 글의 좋아요 알림은 같은 사람에게서 하루 한 번만 (추천안 #11, 4단계 기본값, 확인 대기).
- 댓글은 회원당 1분에 10개, 최근 검색어는 10개까지 저장 (4단계 기본값, 확인 대기).
- 차단은 양쪽 방향으로 보고, 4단계에서는 검색·피드에서만 서로의 글을 뺀다. 댓글을 막는 것은 차단 화면이 생기는 5단계에서.
- 카테고리 이름은 1~20자, 같은 블로그 안에서 중복 불가로 두었다 (3단계 기본값, 확인 대기).
- 본문에는 이 사이트에 올린 사진만 넣을 수 있다. 바깥 사이트 사진 주소는 걸러 낸다 (CSP `img-src 'self'`, 3단계 기본값, 확인 대기).

- 6.6 "수정 표시"는 "수정한 글과 댓글에 '수정됨' 표시 — 댓글만"으로 적혀 있어, **댓글에만** "수정됨"을 표시하는 것으로 읽었다.
- 블로그 공지(블로그장이 작성)는 그 블로그의 글 중 공지로 표시된 글로 본다. 메인 공지사항(BRD-10)과는 별개다.
