# Feature Specification: 소셜과 알림 (팔로우·구독·프로필·차단·신고·알림)

**Feature Branch**: `003-social-notification`

**Created**: 2026-10-07

**Status**: Draft (요구사항 확정, 구현 계획 전)

**Input**: 요구사항분석서 1편 3.3 소셜(SOC-01~06), 3.6 알림, 4.4 가림 표시, 4.5 데이터 보관 / 2편 6.5 중복 규칙, 6.7 알림 보관, 7장 알림 전달

## 범위

소셜 기능은 회원 단위로 메인에서 한 번만 만들고, 모든 개별 블로그가 같은 프로필·알림·차단 정보를 씁니다.

- 포함: 회원 팔로우, 블로그 구독, 팔로워·팔로잉 목록, 프로필, 차단, 신고 접수, 알림(종 아이콘·사이드바·설정·보관)
- 제외: 메인 피드 화면(→ [004 BRD-09](../004-board/spec.md)), 신고 처리(블로그 안 → [002 BLG-13](../002-blog-management/spec.md), 블로그·블로그장 → [005 ADM-04](../005-admin-moderation/spec.md))

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 알림 받기 (Priority: P1)

회원이 종 아이콘을 눌러 오른쪽 사이드바에서 탭별로 알림을 보고, 읽음 처리하거나 지운다.

**Why this priority**: 참여 승인, 위임 요청, 폐쇄 예정처럼 블로그 운영의 핵심 흐름이 알림으로 전달된다.

**Independent Test**: 다른 회원이 내 글에 댓글을 달면 30초 안에 종 아이콘에 표시되고, 사이드바의 "댓글" 탭과 "전체" 탭에서 보이면 통과.

**Acceptance Scenarios**:

1. **Given** 로그인 상태, **When** 화면이 열려 있으면, **Then** 30초마다 새 알림을 확인한다. 이 자동 확인은 로그인 연장(30분 무활동)에 세지 않는다 (D-62, D-72).
2. **Given** 안 읽은 알림, **When** 읽으면, **Then** 강조 색이 사라져 안 읽은 알림과 구분된다.
3. **Given** 알림 여러 개, **When** 일괄 삭제하면, **Then** 모두 지워진다.
4. **Given** 내 정보 > 알림 설정, **When** 끌 수 있는 알림을 끄면, **Then** 그 뒤로 그 종류의 새 알림이 만들어지지 않고, 이미 받은 알림은 그대로 남는다.
5. **Given** 끌 수 없는 알림(위임 요청, 폐쇄 예정 등), **When** 설정 화면을 보면, **Then** 끌 수 없게 되어 있다.
6. **Given** 받은 지 30일 지난 알림, **When** 04:00 배치가 돌면, **Then** 삭제된다. 회원이 보관 기간을 7일로 줄였으면 7일 뒤 삭제된다.

---

### User Story 2 - 팔로우와 구독 (Priority: P2)

회원이 다른 회원을 팔로우하고 블로그를 구독해, 메인 피드의 탭에서 새 글을 본다.

**Why this priority**: 사람을 따라가는 것과 블로그를 따라가는 것은 목적이 달라 둘 다 둔다 (D-02).

**Independent Test**: 팔로우한 회원의 새 글이 피드의 팔로우 탭에, 구독한 블로그의 새 글이 구독 탭에 보이면 통과.

**Acceptance Scenarios**:

1. **Given** 이미 팔로우한 회원, **When** 다시 팔로우를 누르면, **Then** 팔로우가 취소된다. 구독·좋아요도 같다.
2. **Given** 누가 나를 팔로우, **When** 팔로우가 되면, **Then** 나에게 "새 팔로워" 알림이 간다.
3. **Given** 누가 내 블로그를 구독, **When** 구독이 되면, **Then** 블로그장에게 알림이 간다.
4. **Given** 프로필 화면, **When** 팔로워·팔로잉 목록을 열면, **Then** 목록이 보인다.

---

### User Story 3 - 프로필 보기 (Priority: P2)

누구나 회원의 프로필에서 닉네임·사진·소개·운영하는 블로그·참여한 블로그·팔로워 수를 본다.

**Why this priority**: 팔로우할지 정하는 기준이고, 다른 회원의 개인정보가 새지 않아야 한다.

**Independent Test**: 다른 회원의 프로필 API 응답에 이메일·이름·전화번호가 없으면 통과.

**Acceptance Scenarios**:

1. **Given** 다른 회원의 프로필, **When** 보면, **Then** 닉네임·프로필 사진·소개·운영 블로그·참여 블로그·팔로워 수만 보이고 이메일·이름·전화번호는 응답에도 없다 (4.4).

---

### User Story 4 - 차단 (Priority: P3)

회원이 불편한 회원을 차단해 그 사람의 글과 댓글을 숨긴다.

**Why this priority**: 개인이 스스로 불편을 줄이는 수단이다.

**Independent Test**: 차단하면 서로의 팔로우가 풀리고 그 사람의 글·댓글이 숨겨지되, 같은 블로그 멤버끼리는 그 블로그 안의 글이 보이면 통과.

**Acceptance Scenarios**:

1. **Given** 서로 팔로우 중, **When** 한쪽이 차단하면, **Then** 서로의 팔로우가 해제된다.
2. **Given** 차단한 회원, **When** 피드·검색·댓글을 보면, **Then** 그 사람의 글과 댓글이 숨겨진다.
3. **Given** 차단한 회원과 같은 블로그의 멤버, **When** 그 블로그 안의 글을 보면, **Then** 보인다 (D-36).
4. **Given** 블로그장이 차단한 회원, **When** 그 블로그에 참여 신청하면, **Then** 자동으로 거절된다.

---

### User Story 5 - 신고 (Priority: P2)

회원이 회원·블로그·글·댓글을 사유를 골라 신고하고, 처리 결과를 알림으로 받는다.

**Why this priority**: 블로그장과 관리자의 제재가 신고에서 시작한다.

**Independent Test**: 블로그 안의 글 신고는 그 블로그의 블로그장에게, 블로그 자체 신고는 메인 관리자에게 접수되면 통과.

**Acceptance Scenarios**:

1. **Given** 블로그 안의 회원·글·댓글, **When** 신고하면, **Then** 그 블로그의 블로그장(멤버 관리 권한이 있는 부블로그장 포함)에게 접수된다.
2. **Given** 블로그 자체, 블로그장, 블로그장이 쓴 글·댓글, **When** 신고하면, **Then** 메인 관리자에게 접수된다 (D-45, D-85).
3. **Given** 메인 프로필 화면, **When** 회원을 신고하면, **Then** 메인 관리자에게 접수된다 (D-85).
4. **Given** 같은 대상을 신고한 지 2주가 안 됨, **When** 다시 신고하면, **Then** 거절된다.
5. **Given** 신고가 처리됨, **When** 결과가 나오면, **Then** 신고자에게 알림이 간다.

### Edge Cases

- 탈퇴한 회원은 팔로워·팔로잉 목록에서 빠진다.
- 비공개로 바뀐 블로그의 구독은 유지되지만 멤버가 아닌 구독자에게는 글이 보이지 않는다 (D-37).
- 폐쇄된 블로그의 구독은 블로그가 폐쇄되면 의미가 없어진다. 폐쇄 알림은 구독자에게도 간다.
- 알림을 끈 동안 생긴 일은 다시 켜도 알림으로 만들어지지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **SOC-01 팔로우·구독** (중, D-02, BRD-09): 다른 회원을 팔로우·취소한다. 블로그도 구독·취소한다. 한 번만, 다시 누르면 취소.
- **SOC-02 팔로워·팔로잉 목록** (하): 프로필에서 본다.
- **SOC-03 프로필** (상): 닉네임, 사진, 소개, 운영하는 블로그, 참여한 블로그, 팔로워 수.
- **SOC-04 알림** (중): 아래 알림 표의 종류를 보내고, 읽음 처리와 전체 삭제를 지원한다. 종 아이콘 → 사이드바 탭, 내 정보에서 종류별 켜고 끄기 (D-39, D-56). 30초 폴링 (D-72).
- **SOC-05 차단** (하): 차단한 회원의 글과 댓글을 숨기고 서로의 팔로우를 해제한다. 같은 블로그 멤버끼리는 그 블로그 안의 글이 보인다. 블로그장이 차단한 회원의 참여 신청은 자동 거절 (D-36).
- **SOC-07 내 활동** (중, D-91): [내 활동] 화면에서 내가 쓴 글, 쓴 댓글(D-94), 좋아요 한 글, 팔로잉, 구독한 블로그를 탭으로 본다. 목록마다 "다른 사람에게 보여주기" 체크를 두고 기본은 켜짐. 켜 둔 목록은 프로필에서 다른 사람도 보되, 그 사람이 볼 수 있는 글·블로그만 나온다.
- **SOC-06 신고** (중, ADM-04, BLG-13): 회원·블로그·게시글·댓글을 사유를 골라 신고한다. 블로그 안의 멤버와 그 글·댓글은 블로그장, 블로그·블로그장(블로그장의 글·댓글 포함)·메인 프로필에서 한 회원 신고는 메인 관리자에게 접수 (D-45, D-85). 같은 대상은 한 사람이 2주에 한 번.

### 알림 종류 (3.6)

탭은 **전체**(맨 앞), 댓글, 좋아요, 팔로우·구독, 블로그, 운영입니다.

| 탭 | 알림 | 언제 | 받는 사람 | 끌 수 있음 |
|---|---|---|---|---|
| 댓글 | 내 글에 댓글 | 댓글이 달릴 때 | 글 작성자 | O |
| 댓글 | 내 댓글에 대댓글 | 대댓글이 달릴 때 | 댓글 작성자 | O |
| 좋아요 | 내 글 좋아요 | 좋아요를 받을 때 | 글 작성자 | O |
| 팔로우·구독 | 새 팔로워 | 누가 나를 팔로우할 때 | 팔로우받은 회원 | O |
| 팔로우·구독 | 블로그 구독 | 누가 내 블로그를 구독할 때 | 블로그장 | O |
| 블로그 | 참여 신청 | 승인제 블로그에 신청이 올 때 | 블로그장, 승인 권한이 있는 부블로그장 | O |
| 블로그 | 참여 승인·거절 | 신청이 처리될 때 | 신청한 회원 | O |
| 블로그 | 위임 요청 | 위임 요청을 받을 때 | 받는 멤버 | X |
| 블로그 | 위임 수락·거절·자동 취소 | 응답하거나 7일이 지날 때 | 블로그장 | X |
| 블로그 | 폐쇄 예정 | 버튼을 누른 즉시, 3일 전, 1일 전 | 블로그장을 뺀 멤버, 구독자 | X |
| 블로그 | 폐쇄 철회 | 블로그장이 철회할 때 | 블로그장을 뺀 멤버, 구독자 | X |
| 블로그 | 비공개 전환 | 블로그가 비공개로 바뀔 때 | 구독자 | X |
| 블로그 | 블랙리스트 해제 문의 결과 | 블로그장이 처리할 때 | 문의한 회원 | X |
| 운영 | 내 글 삭제됨 | 관리자나 블로그장이 삭제할 때 | 글 작성자 | X |
| 운영 | 신고 처리 결과 | 블로그장이나 관리자가 처리할 때 | 신고한 회원 | O |
| 운영 | 경고·정지·정지 해제·강제 퇴장 | 블로그장이 조치할 때 (BLG-13) | 대상 회원 | X |
| 운영 | 블로그장 경고·권한 박탈 | 관리자가 조치할 때 (ADM-07) | 블로그장 | X |
| 운영 | 공지사항 | 관리자가 올릴 때 | 전체 회원 | O |

- 계정과 블로그 운영에 꼭 필요한 알림은 끌 수 없다. 예: 폐쇄 예정 알림을 끄면 자기 글을 챙길 기회를 놓친다.
- 알림 보관: 기본 30일 뒤 삭제(4.5). 내 정보에서 7일로 줄이거나 직접 일괄 삭제할 수 있다(6.7). 블로그장은 블로그 알림 보관도 7일 또는 일괄 삭제로 설정한다.

### Key Entities

- **팔로우**: 팔로우하는 회원 → 팔로우받는 회원. (회원, 회원) 고유.
- **구독**: 회원 → 블로그. (회원, 블로그) 고유.
- **차단**: 차단한 회원 → 차단당한 회원.
- **신고**: 신고자, 대상 종류(회원·블로그·글·댓글), 대상, 사유, 접수처(블로그장·메인 관리자), 처리 결과, 신고 시각(2주 제한 계산). 1년 보관 (D-60).
- **알림**: 받는 회원, 종류, 탭, 관련 대상, 읽음 여부, 받은 시각.
- **알림 설정**: 회원 × 끌 수 있는 알림 종류, 켜짐 여부, 보관 기간(30일·7일).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 알림을 만드는 일이 생기고 30초 안에 받는 사람 화면의 종 아이콘에 표시된다.
- **SC-002**: 끌 수 없는 알림은 어떤 설정 요청으로도 꺼지지 않는다.
- **SC-003**: 다른 회원의 프로필·팔로워 목록 API 응답에 이메일·이름·전화번호가 들어 있지 않다.
- **SC-004**: 한 사람이 같은 대상을 2주 안에 두 번 신고할 수 없다.

## Clarifications

### 결정 기록에서 옮김 (2026-10-02 ~ 2026-10-06)

- Q: 팔로우와 구독을 둘 다 두나? → A: 둘 다 둠 (D-02)
- Q: 차단과 블로그 운영이 부딪히면? → A: 같은 블로그 안에서는 보임, 블로그장이 차단한 회원의 신청은 자동 거절 (D-36)
- Q: 신고는 누가 처리하나? → A: 블로그 안은 블로그장, 블로그·블로그장은 메인 관리자 (D-45)
- Q: 알림을 어떻게 보여주나? → A: 종 아이콘 → 사이드바 탭, 내 정보에서 종류별 켜기·끄기 (D-39). 끌 수 있는 범위와 탭 확정, 읽은 알림은 강조 색 제거 (D-56)
- Q: 알림 전달 방식은? → A: 30초 폴링. SSE·WebSocket은 제외 (D-72)

### 2026-10-07 팀 결정 (김채림)

- Q: 블로그장 본인이나 블로그장의 글·댓글, 메인 프로필에서 한 신고는 누가 처리하나? → A: 메인 관리자 (D-85)

### 2026-10-08 사용자 요청 (김채림)

- Q: 내가 쓴 글·좋아요 한 글·팔로잉·구독 목록을 모아 볼 곳은? → A: [내 활동] 화면, 목록마다 공개 체크(기본 공개) (D-91, SOC-07)
- Q: [내 활동]에 내가 쓴 댓글도 볼 수 있나? → A: "쓴 댓글" 탭 추가, 누르면 그 댓글 자리로. 공개 체크 기본 켜짐 (D-94)
