# Feature Specification: 회원관리 (가입·로그인·계정)

**Feature Branch**: `001-member-account`

**Created**: 2026-10-07

**Status**: Draft (요구사항 확정, 구현 계획 전)

**Input**: 요구사항분석서 1편 3.1 회원관리(USR-01~08), 4.1 보안(SEC-01~05, SEC-13), 4.4 가림 표시, 4.6 개인정보 처리 / 2편 6.5 중복 규칙, 6.7 회원·보안·운영 숫자

## 범위

회원 계정은 메인블로그 한 곳에서만 만들고, 모든 개별 블로그가 이 계정을 같이 씁니다. 이메일이 곧 아이디입니다.

- 포함: 가입(이메일 인증), 로그인·로그아웃, 로그인 유지, 비밀번호 찾기·재설정, 이메일 찾기, 회원정보 수정, 회원탈퇴, 개인정보 동의, 구글 로그인 (D-103), 네이버 로그인 (D-107), 카카오 로그인 (D-108)
- 제외: 문자(SMS) 인증(2차), 구글·네이버·카카오 외 소셜 로그인, 블로그별 역할 확인(→ [002](../002-blog-management/spec.md))

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 이메일 인증으로 가입하기 (Priority: P1)

방문자가 이메일로 6자리 인증번호를 받아 인증한 뒤, 비밀번호를 정하고 이름·닉네임·전화번호를 입력해 가입한다.

**Why this priority**: 계정이 없으면 블로그 생성·참여·소셜 등 다른 모든 기능을 쓸 수 없다.

**Independent Test**: 새 이메일로 세 단계를 끝까지 진행해 가입되고, 그 계정으로 로그인할 수 있으면 통과.

**Acceptance Scenarios**:

1. **Given** 가입하지 않은 이메일, **When** 인증번호를 요청하면, **Then** 화면에 "인증번호를 보냈습니다"가 보이고 6자리 인증번호 메일이 간다.
2. **Given** 이미 가입된 이메일, **When** [중복 확인]을 누르거나 인증번호를 요청하면, **Then** 화면에 "이미 가입된 이메일입니다"가 보이고 메일은 가지 않는다 (D-99).
3. **Given** 인증번호를 받은 상태, **When** 10분 안에 맞게 입력하면, **Then** 비밀번호 입력 단계로 넘어간다.
4. **Given** 인증번호를 받은 상태, **When** 5번 틀리거나 10분이 지나면, **Then** 그 인증번호는 무효가 되고 다시 요청해야 한다.
5. **Given** 인증번호를 보낸 지 1분이 안 됐을 때, **When** 다시 보내기를 누르면, **Then** 거절된다. 1분이 지나 다시 보내면 이전 번호는 무효가 된다.
6. **Given** 화면에서 인증 단계를 건너뛰고 마지막 단계 요청을 직접 보낸 경우, **When** 가입을 요청하면, **Then** 서버가 이메일 인증 완료 여부를 다시 확인해 거절한다.
7. **Given** 세 번째 단계, **When** 필수 동의(이용약관, 개인정보 수집·이용, 만 14세 이상) 중 하나라도 체크하지 않으면, **Then** 가입되지 않는다.

### User Story 2 - 로그인과 로그아웃 (Priority: P1)

회원이 이메일과 비밀번호로 로그인하고, 로그인 상태는 모든 개별 블로그에서 유지된다.

**Why this priority**: 글쓰기·참여·댓글 등 회원 기능의 전제다.

**Independent Test**: 로그인 후 `/blog/{주소}`로 이동해도 로그인 상태가 같게 보이고, 로그아웃하면 즉시 비회원이 되면 통과.

**Acceptance Scenarios**:

1. **Given** "로그인 유지"를 체크하지 않고 로그인, **When** 브라우저를 닫거나 30분 동안 직접 한 행동이 없으면, **Then** 로그아웃된다.
2. **Given** "로그인 유지"를 체크하고 로그인, **When** 14일 안에 다시 오면, **Then** 로그인 상태다.
3. **Given** 로그인 상태, **When** 알림 자동 확인(30초 폴링)만 오가고 스크롤·마우스 움직임만 있으면, **Then** 30분 무활동 시간은 다시 시작되지 않는다 (D-62).
4. **Given** 글쓰기 화면에서 입력 중, **When** 몇 분이 지나면, **Then** 연장 요청이 가고, 만료 5분 전에는 "로그인을 연장할까요?" 창이 뜬다.
5. **Given** 로그인을 3번 실패, **When** 다시 로그인하려 하면, **Then** 사람 확인(Cloudflare Turnstile)이 나온다.
6. **Given** 로그인을 5번 연속 실패, **When** 다시 시도하면, **Then** 5분 동안 잠긴다.
7. **Given** 로그인 상태, **When** 로그아웃하면, **Then** 서버가 Refresh Token을 폐기하고 토큰 쿠키를 지운 뒤 메인으로 이동한다.

### User Story 3 - 비밀번호 찾기·재설정 (Priority: P2)

비밀번호를 잊은 회원이 이메일로 받은 6자리 인증번호로 같은 화면에서 새 비밀번호를 정한다.

**Why this priority**: 가입·로그인 다음으로 계정을 잃지 않게 하는 기본 기능이다.

**Independent Test**: 비밀번호 찾기로 새 비밀번호를 정한 뒤 새 비밀번호로 로그인되고, 다른 기기의 로그인은 풀리면 통과.

**Acceptance Scenarios**:

1. **Given** 가입 여부와 관계없이, **When** 이메일을 입력하면, **Then** 화면에는 "입력한 이메일로 안내를 보냈습니다"가 똑같이 보인다.
2. **Given** 인증번호를 받은 상태, **When** 30분 안에 맞게 입력하고 새 비밀번호를 두 번 입력하면, **Then** 비밀번호가 바뀌고 다른 기기의 로그인이 모두 풀리며 로그인 잠금도 풀린다.
3. **Given** 한 번 쓴 인증번호, **When** 다시 쓰면, **Then** 거절된다. 5번 틀려도 무효가 된다.

---

### User Story 4 - 이메일 찾기 (Priority: P3)

이메일(아이디)을 잊은 사람이 이름과 전화번호로 가려진 이메일을 찾고, 바로 비밀번호 재설정까지 이어간다.

**Why this priority**: 자주 쓰지 않지만 이메일과 비밀번호를 모두 잊은 사람을 구제한다.

**Independent Test**: 이름·전화번호로 가려진 이메일과 가입일이 보이고, [비밀번호 재설정]으로 새 비밀번호를 정할 수 있으면 통과.

**Acceptance Scenarios**:

1. **Given** 일치하는 계정이 여러 개, **When** 이름과 전화번호를 입력하면, **Then** 모두 가려서 가입일과 함께 보여준다 (예: `ab***@gmail.com, 2026.10.02 가입`). 탈퇴한 계정은 뺀다.
2. **Given** 일치하는 계정이 없음, **When** 찾으면, **Then** "일치하는 회원 정보가 없습니다"가 보인다.
3. **Given** 결과 화면, **When** [비밀번호 재설정]을 누르면, **Then** 회원 번호가 아니라 10분짜리 임시 토큰으로 요청하고, 그 이메일로 인증번호가 간다 (D-26).
4. **Given** 같은 IP, **When** 10분 안에 6번째로 찾으면, **Then** 거절된다.

---

### User Story 5 - 회원정보 수정과 탈퇴 (Priority: P2)

회원이 닉네임·프로필 사진·전화번호·비밀번호를 바꾸고, 필요하면 탈퇴한다.

**Why this priority**: 계정 관리의 기본이고, 탈퇴는 블로그 위임·폐쇄 규칙과 맞물린다.

**Independent Test**: 정보 수정이 본인에게만 허용되고, 운영 중인 블로그가 있는 블로그장은 탈퇴가 막히면 통과.

**Acceptance Scenarios**:

1. **Given** 내 정보 화면, **When** 이메일이나 이름을 바꾸려 하면, **Then** 바꿀 수 없다 (D-21, D-32).
2. **Given** 비밀번호 변경, **When** 현재 비밀번호가 틀리면, **Then** 바뀌지 않는다. 바뀌면 서버의 Refresh Token을 폐기한다.
3. **Given** 블로그장인 블로그가 있음(폐쇄 예정 7일 포함), **When** 탈퇴하려 하면, **Then** 운영 중인 블로그 목록을 보여주고 블로그마다 위임이나 폐쇄가 끝날 때까지 탈퇴할 수 없다 (D-15, D-18).
4. **Given** 탈퇴 조건을 만족, **When** 비밀번호를 다시 확인하고 탈퇴하면, **Then** 로그인용 이메일을 즉시 비워 같은 이메일로 바로 재가입할 수 있고, 쓴 글은 "탈퇴한 회원"으로 남는다.

### Edge Cases

- 대소문자만 다른 이메일(`A@x.com`, `a@x.com`)은 같은 이메일로 본다. 소문자로 바꿔 저장한다.
- 닉네임 예약어(관리자, admin, 운영자, 탈퇴한 회원)는 쓸 수 없다.
- 전화번호는 1차에 중복을 허용한다. 같은 번호로 여러 계정이 있으면 이메일 찾기 결과에 모두 나온다.
- 비밀번호를 바꾸거나 재설정하는 순간 다른 기기의 로그인은 다음 요청에서 풀린다.
- 정지는 블로그 단위라, 어떤 블로그에서 정지된 회원도 로그인은 된다 (D-43).
- 탈퇴 뒤 같은 이메일로 다시 가입해도 예전 글과는 연결되지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **USR-01 회원가입** (상, SEC-01·02): ① 이메일 인증 → ② 비밀번호 → ③ 이름·닉네임·전화번호 순서로 진행하고 모두 끝나야 가입된다. 이메일·닉네임은 중복 불가. 전화번호는 숫자만 저장하고 1차에는 중복 허용(D-24).
- **USR-02 이메일 인증** (중): 6자리 인증번호를 Spring 서버가 `SecureRandom`으로 만들어 Gmail SMTP로 보낸다. 이메일 기준으로 해시해 DB에 저장, 10분 만료, 5번 틀리면 무효, 다시 보내기는 1분에 한 번(이전 번호 무효). 가입 화면에는 이메일 중복 확인 버튼을 두고 IP별로 횟수를 제한한다(D-99, D-28을 가입 화면에서만 바꿈).
- **USR-03 로그인** (상, SEC-03·04): 이메일과 비밀번호로 로그인. 로그인 상태는 모든 개별 블로그에서 유지. "로그인 유지" 체크박스.
- **USR-04 로그아웃** (상, SEC-04): 서버에서 Refresh Token 폐기, 토큰 쿠키 삭제, 메인으로 이동.
- **USR-05 회원탈퇴** (상, BLG-08·09): 비밀번호 재확인. 블로그장인 블로그가 있으면 위임·폐쇄가 끝난 뒤에만 탈퇴. 글은 "탈퇴한 회원"으로 남음.
- **USR-06 비밀번호 찾기·재설정** (중, SEC-05): 6자리 인증번호, 30분 만료, 1회용, 5번 틀리면 무효. 같은 화면에서 새 비밀번호 두 번 입력. 바뀌면 다른 기기 로그아웃, 로그인 잠금 해제. 가입 여부와 관계없이 같은 문구.
- **USR-07 회원정보 수정** (중, SEC-02): 닉네임·프로필 사진·전화번호·비밀번호 수정. 본인만. 비밀번호 변경 시 현재 비밀번호 확인. 이메일·이름은 수정 불가.
- **USR-08 이메일 찾기** (중): 이름(앞뒤 공백 제거)·전화번호(숫자만)로 찾아 가린 이메일과 가입일 표시. 탈퇴 계정 제외. 재설정 요청은 10분 임시 토큰으로. 같은 IP는 10분에 5번까지.

### 보안 요구사항 (4.1에서 이 기능에 걸리는 것)

- **SEC-01**: 비밀번호는 bcrypt 해시로만 저장 (D-81).
- **SEC-02**: 비밀번호 8~15자, 영문·숫자·특수문자 모두 포함, 대소문자 구분.
- **SEC-03**: 로그인 5회 연속 실패 시 5분 잠금. 계정별 잠금 + IP별 요청 제한 (D-80).
- **SEC-04**: JWT를 HttpOnly·Secure 쿠키에 담음(localStorage 금지). 짧은 Access Token + Refresh Token. Refresh Token은 서버(DB)에 저장해 로그아웃·비밀번호 변경 때 폐기. 로그인 유지 미체크 시 만료 없는 세션 쿠키 + 30분 무활동 로그아웃, 체크 시 14일 (D-53, D-61, D-62).
- **SEC-05**: 비밀번호 재설정 인증번호 1회용, 30분 만료, 5번 틀리면 무효.
- **SEC-13**: 로그인 3번 실패 뒤부터 Cloudflare Turnstile 사람 확인 (D-79).

### 입력 규칙 (6.5, 6.7)

| 항목 | 규칙 |
|---|---|
| 이메일 | 중복 불가, 소문자로 바꿔 저장 |
| 닉네임 | 중복 불가, 2~12자, 한글·영문·숫자. 예약어(관리자, admin, 운영자, 탈퇴한 회원) 불가 |
| 비밀번호 | 8~15자, 영문·숫자·특수문자 모두 포함, 대소문자 구분 |
| 전화번호 | 숫자만 저장, 1차 중복 허용 |
| 프로필 사진 | 3MB, 1장, jpg·jpeg·png·gif·webp (6.3) |

### 개인정보 (4.4, 4.6)

- 가입 ③단계에서 [필수] 이용약관, [필수] 개인정보 수집·이용 동의, "만 14세 이상입니다"를 각각 체크박스로 받고 동의 시각을 저장한다. 만 14세 미만은 가입 불가.
- 필수: 이메일, 비밀번호, 이름, 닉네임, 전화번호. 선택: 프로필 사진, 소개. 자동 수집: 접속 IP, 브라우저 정보, 쿠키.
- 본인(내 정보)에게는 이메일·이름·닉네임·전화번호를 그대로 보여준다. 이메일 찾기 결과는 가린다.
- 가림 형식: 이메일은 @ 앞 처음 2글자만(2글자 이하면 첫 글자만) + `***`, 전화번호는 가운데 4자리 `****`. 서버가 응답을 만들 때 가린다.
- 모든 화면 아래에 개인정보 처리방침 링크를 둔다.
- 탈퇴한 회원의 개인정보는 30일 뒤 삭제한다. 인증번호와 임시 토큰은 쓰거나 만료되면 바로 삭제한다 (4.5).

### Key Entities

- **회원**: 이메일(소문자, 로그인 아이디), 비밀번호 해시, 이름, 닉네임, 전화번호(숫자), 프로필 사진, 소개, 가입일, 상태(정상·탈퇴), 동의 시각들.
- **이메일 인증번호**: 이메일, 코드 해시, 용도(가입·비밀번호 재설정), 만료 시각, 틀린 횟수, 사용 여부, 인증 완료 여부.
- **Refresh Token**: 회원, 토큰 해시, 만료 시각, 로그인 유지 여부. 로그아웃·비밀번호 변경 시 폐기.
- **로그인 실패 기록**: 회원(또는 이메일), 연속 실패 횟수, 잠금 해제 시각. DB에 저장 (SCL-01).
- **이메일 찾기 임시 토큰**: 대상 회원, 10분 만료.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 가입 화면을 벗어나지 않고 세 단계만으로 가입이 끝난다.
- **SC-002**: 가입·비밀번호 찾기·이메일 찾기 어느 화면에서도 응답 문구나 응답 형태로 특정 이메일의 가입 여부를 알아낼 수 없다.
- **SC-003**: 로그아웃이나 비밀번호 변경 뒤 이전 Refresh Token으로는 다시 로그인 상태를 만들 수 없다.
- **SC-004**: DB와 로그 어디에도 비밀번호·인증번호 평문이 남지 않는다.
- **SC-005**: 서버를 2대로 늘려도 인증번호 검증·로그인 실패 횟수·잠금이 어느 서버로 가든 같게 동작한다.
