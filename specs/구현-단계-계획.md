# 메인블로그 구현 단계 계획 (2026-10-08)

근거 자료: 헌법·spec 001~005·결정 D-84~D-88 (PR #1), ERD·schema.sql 34개 테이블 (PR #2).
각 단계는 Spec Kit으로 `/speckit-plan → /speckit-tasks → /speckit-implement` 한 바퀴씩 돕니다.
단계가 끝날 때마다 서버를 띄워 브라우저로 직접 눌러 보고, 자동 테스트도 함께 통과해야 다음 단계로 갑니다.
단계마다 끝낸 내용은 [진행-기록.md](진행-기록.md)에 정리합니다.

### 1단계: 뼈대 + 가입·로그인

- 만들 것: Spring Boot 프로젝트, MySQL 연결과 schema.sql 적용(Flyway 권장), Spring Security(보안 헤더·CSRF·JWT 쿠키), 공통 `api.js`, 공통 화면 틀, 이메일 6자리 인증 가입, 로그인·로그아웃, "로그인 유지", 계정 잠금, IP별 요청 제한(저장소 인터페이스).
- 이 단계에서 공통 규칙(XSS 출력 방식, CSRF, 비밀번호 bcrypt)을 한 번 제대로 깔아 두면 이후 단계는 기능만 얹습니다.
- 테스트: 가입 → 메일로 온 인증번호 입력 → 로그인 → 새로고침해도 유지 → 로그아웃. 비밀번호 5번 틀려 잠기는지, `X-XSRF-TOKEN` 없는 요청이 403인지, DB에 비밀번호가 bcrypt로 들어갔는지.

### 2단계: 계정 나머지 + 블로그

- 만들 것: 비밀번호 찾기·재설정, 이메일 찾기, 회원정보 수정·탈퇴, 블로그 생성(주소 `/blog/{주소}`, 공개 3개 제한), 블로그 목록·검색, 참여 신청·승인, 내 블로그 목록, 블로그 탈퇴, 블로그별 역할(블로그장·부블로그장·멤버) 확인.
- 테스트: 계정 A가 블로그를 만들고, 계정 B가 찾아서 참여 신청 → A가 승인 → B의 "내 블로그"에 보임. 공개 블로그 4번째 생성이 막히는지, 동시에 눌러도 3개를 넘지 않는지.

### 3단계: 글쓰기·읽기

- 만들 것: Toast UI Editor 글쓰기, 서버 마크다운→HTML 변환 + jsoup 필터, 글 상세(og 태그), 수정·삭제 권한, 카테고리·태그, 글 목록, 이미지 업로드(세 겹 검사, EXIF 제거).
- 여기까지 오면 "블로그를 만들고 글을 쓰고 읽는" 기본 블로그가 완성됩니다.
- 테스트: 글에 `<script>`를 넣어도 실행되지 않는지, 멤버가 남의 글 수정 시 403인지, 확장자만 .jpg로 바꾼 파일이 막히는지, 카톡·슬랙에 글 주소를 붙였을 때 미리보기가 뜨는지.

### 4단계: 댓글·좋아요·검색·피드

- 만들 것: 댓글(수정됨 표시), 좋아요, 통합 검색(FULLTEXT + ngram), 메인 피드·공지, 링크 복사 공유, 조회수.
- 테스트: 한글 두 글자 검색이 되는지, 같은 사람이 여러 번 열어도 조회수가 하루 1번만 오르는지, 검색·피드가 1초 안에 뜨는지(샘플 글 수천 건 넣고).

### 5단계: 소셜·알림

- 만들 것: 팔로우·구독, 프로필, 차단, 신고, 알림(30초 폴링), [내 활동] 화면(쓴 글·좋아요 한 글·팔로잉·구독, 목록별 공개 체크, D-91).
- 테스트: B가 A를 구독 → A가 글을 쓰면 B에게 30초 안에 알림. 차단하면 서로 글·댓글이 안 보이고 댓글을 못 다는지.

### 6단계: 제재 + 관리자

- 만들 것: 블로그장 위임·폐쇄(7일 뒤 04:00, 철회), 멤버 경고·정지·강퇴·블랙리스트, 관리자 계정·로그인, 신고 처리, 블로그 숨김·강제 폐쇄, 회원 조회·개인정보 열람 기록, 통계, 활동 기록, 04:00 배치(ShedLock).
- 테스트: 폐쇄 예약 후 철회되는지, 배치 시간을 당겨 실제로 폐쇄되는지, 강퇴된 멤버가 블랙리스트로 다시 참여하지 못하는지, 관리자가 개인정보 "전체 보기"를 누르면 기록이 남는지.

## 왜 6개인가

- 001~005 spec을 그대로 5개로 나누면 004 게시판이 너무 커서(US 8개) 한 번에 테스트하기 어렵고, 003 알림은 글이 있어야 테스트할 수 있습니다.
- 반대로 10개 이상으로 쪼개면 단계마다 "눌러 볼 화면"이 너무 작아집니다.
- 그래서 **"사람이 브라우저로 한 흐름을 끝까지 눌러 볼 수 있는가"** 를 기준으로 6개로 묶었습니다. 3단계가 끝나면 최소한의 블로그가 돌아가고, 4~6단계는 그 위에 붙는 기능입니다.
