# 기능 명세 (Spec Kit)

보안(SEC)·확장성(SCL)·기술 스택(7장)처럼 모든 기능에 걸리는 규칙은 헌법에 모았습니다. spec의 요구사항 번호는 Spec Kit 기본값(`FR-001`) 대신 원래 요구사항 ID(`USR-01` 등)를 그대로 씁니다.

## 개발 순서 (권장)

1. 001 회원관리 → 2. 002 블로그 관리 → 3. 004 게시판 → 4. 003 소셜·알림 → 5. 005 관리자

실제 구현은 테스트할 수 있는 6단계로 나눠 진행합니다. 단계별 내용·테스트 방법·먼저 정할 항목은 [구현-단계-계획.md](구현-단계-계획.md)에 있습니다. 1단계(뼈대 + 001 가입·로그인)의 계획과 작업 목록은 [001 plan.md](001-member-account/plan.md), [001 tasks.md](001-member-account/tasks.md)에, 2단계(계정 나머지 + 블로그 만들기·참여)는 [002 plan.md](002-blog-management/plan.md), [002 tasks.md](002-blog-management/tasks.md)에, 3단계(글쓰기·읽기)는 [004 plan.md](004-board/plan.md), [004 tasks.md](004-board/tasks.md)에 있습니다. 단계마다 끝낸 내용은 [진행-기록.md](진행-기록.md)에 정리합니다.

계정과 블로그별 역할이 있어야 글쓰기·알림·제재를 만들 수 있기 때문입니다. 각 기능은 `/speckit-clarify`로 남은 질문을 정리한 뒤 `/speckit-plan`으로 들어갑니다. DB 설계(ERD)는 `/speckit-plan`의 data-model 단계에서 합니다(D-47).

Spec Kit 명령은 지금 작업 중인 기능을 `.specify/feature.json`에서 찾습니다. 처음 한 번 `{"feature_directory": "specs/001-member-account"}`처럼 만들어 두거나, 명령을 부를 때 기능 폴더를 함께 적어 주세요. 이 파일은 컴퓨터마다 달라서 git에 올리지 않습니다.

## PDF와 다르게 정리한 점

원본 PDF는 고치지 않고 그대로 두었습니다. 옮기면서 아래처럼 정리했습니다.

- 결정 기록 D-22, D-39, D-40, D-41이 가리키는 6.8~6.11은 지금 PDF에서 각각 4.4(가림 표시), 3.6(알림), 4.5(데이터 보관), 4.6(개인정보)로 옮겨져 있어, spec에는 새 위치로 적었습니다.
- D-29는 정지를 ADM-01로 적었지만 이후 D-43·D-44로 정지가 블로그 단위(BLG-13)로 바뀌어, spec은 BLG-13 기준으로 적었습니다.
- D-64의 `th:text`(Thymeleaf)는 D-66으로 화면이 정적 HTML + JS로 바뀌어 `textContent`만 남겼습니다.
- 6.2 미리보기 칸의 "ulr 최상단, 제목 상단후 닉네임까지, 이미지중단"은 D-59 "주소 → 제목 → 이미지 순서"로 적었습니다.
- 6.7 "로그인 잠금 … 또는 매크로 방지 기능 추가 생각"은 D-80(계정별 잠금 + IP별 요청 제한)으로 확정된 내용으로 적었습니다.
- 6.6 "수정 표시 … 댓글만"은 댓글에만 "수정됨"을 표시하는 것으로 읽었습니다 (004 Assumptions).
