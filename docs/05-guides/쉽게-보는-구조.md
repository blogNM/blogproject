# 쉽게 보는 Creat_ 구조

개발을 몰라도 한 번에 볼 수 있게 "어떤 기술의 어떤 기능으로, 어떻게 했는지"를 모았어요. 발표나 설명할 때 그대로 보여 주면 돼요.
자세한 설정과 명령은 [포트-nginx-롤링배포.md](포트-nginx-롤링배포.md), [도커-배포.md](도커-배포.md)에 있어요.

> **한 문장 요약**: Spring Security가 문지기(로그인·권한 확인)를 하고, 글은 jsoup으로 깨끗이 거른 뒤 MySQL에 두며, GitHub Actions와 Docker가 새 코드를 자동으로 서버에 올려요. 맨 앞에서는 Nginx가 앱 두 대에 손님을 나눠 줘서, 한 대씩 바꿔도 사이트가 멈추지 않아요.

---

## 1. 사이트에 들어온 요청이 지나가는 길

```
브라우저 → 학교 Nginx(443, https 풀기) → 8340 우리 Nginx → 앱 a(8341) 또는 앱 b(8342) → 같은 MySQL · 사진 폴더
```

- **포트**는 건물의 호수예요. 서버 한 대(건물) 안에서 프로그램마다 자기 호수를 가져요.
- **Nginx**는 1층 안내 데스크예요. 손님은 안내 데스크만 보고, 뒤에서 앱이 몇 대 일하는지 몰라요.
- 학교 Nginx는 강사님만 고칠 수 있어서, 8340 자리에 우리 Nginx를 두고 거기서 두 앱에 나눠 줘요 (D-111).

## 2. 서버 두 대 · 끊김 없는 업데이트

| 하는 일 | 쓴 기술 · 기능 | 어떻게 했나 (쉬운 말) |
|---|---|---|
| 앱을 두 대 띄우기 | **Docker** 컨테이너 | 같은 블로그 프로그램을 상자 두 개에 담아 8341·8342 두 호수에 켜 둠 |
| 손님 나눠 주기 | **Nginx**의 `upstream`(로드 밸런싱) | 8340의 안내 데스크가 두 앱에 번갈아 손님을 보냄 |
| 고장 난 앱 피하기 | **Nginx**의 `max_fails`·`proxy_next_upstream` | 한 앱이 대답을 안 하면 5초 동안 빼 두고, 그 요청은 다른 앱에 다시 보내서 손님은 실패를 모름 |
| 어느 앱이 받아도 같게 | **MySQL** 하나 + 공용 사진 폴더 | 두 앱이 같은 창고를 쓰니 어느 쪽에서 글을 써도 똑같이 보임 |
| 로그인 유지 | **Spring Security** + **JWT** 쿠키 | 로그인하면 "출입증"을 브라우저 쿠키에 넣어 줌. 어느 앱이 받아도 출입증만 보면 알아봄 |
| 구글·네이버·카카오 로그인 | **Spring Security OAuth2 Client** | 다른 회사에 로그인하러 다녀오는 동안 확인값을 서버 기억 대신 암호화한 쿠키에 둠. 돌아올 때 다른 앱으로 가도 로그인됨 |
| 자동 배포 | **GitHub Actions** + `deploy.sh` | main에 코드가 합쳐지면 테스트하고 새 버전을 만들어 학교 서버에 보냄 |
| 끊김 없이 바꾸기 | 롤링 배포 + `/api/health` 확인 | 앱 b를 바꾸고 "잘 켜졌나" 확인, 10초 뒤 앱 a를 바꿈. 바꾸는 동안 다른 한 대가 손님을 받음. 안 켜지면 바로 전 버전으로 되돌림 |

결과: 업데이트 중 사이트가 멈추던 시간이 **약 10초 → 0초** ([v1.6.0](../releases/v1.6.0.md)).

> 10초를 기다리는 이유: 새 앱이 켜진 것만으로는 부족하고, 안내 데스크(Nginx)가 "방금 꺼졌던 앱"에 다시 손님을 보내기 시작할 때까지 기다려야 해요. 안 기다렸을 때는 502 에러가 났어요.

## 3. 기능별 흐름

| 흐름 | 쓴 기술 · 기능 | 어떻게 했나 (쉬운 말) |
|---|---|---|
| 로그인 | **Spring Security** + **bcrypt** + **JWT** 쿠키 | 비밀번호는 되돌릴 수 없는 암호로만 저장함. 맞으면 출입증을 쿠키에 넣어 줌. 출입증은 5분짜리이고, 끝나면 `api.js`가 알아서 새로 받아 와서 사용자는 모름 |
| 소셜 로그인 | **OAuth2 Client** | 구글·네이버·카카오가 "이 사람 이메일 맞아요"라고 확인해 준 이메일만 씀. 처음 온 사람은 닉네임·약관만 받고 가입 |
| 글 저장 | **Spring Security**의 CSRF 검사 + 역할 확인, **MySQL** | 요청마다 "진짜 이 사이트 화면에서 보낸 요청인지", "이 블로그 멤버인지"를 확인하고 통과하면 DB에 저장 |
| 글 읽기 | **commonmark** + **jsoup** | 글은 마크다운으로 저장하고, 보여 줄 때 HTML로 바꾼 뒤 위험한 코드(스크립트 등)를 걸러 냄. 닉네임·댓글은 글자 그대로만 보여 줘서 해킹 코드가 실행될 틈이 없음 |
| 링크 미리보기 | 서버가 바깥 사이트 읽기 | 글 속 링크의 제목·사진을 3초 안에 받아 카드로 붙임. 내부망 주소는 안 읽음 |
| 사진 올리기 | 파일 검사 | 확장자·파일 종류·파일 앞부분 서명을 모두 확인하고, 사진 속 위치 정보(GPS)는 지움 |
| 새 글 알림 | MySQL 저장 후 알림 | 저장되면 팔로워·구독자에게 알림, 댓글·좋아요는 글쓴이에게 알림 |
| 코드 → 사이트 반영 | **GitHub Actions** + **Docker** + `deploy.sh` | main에 합치면 테스트 → 프로그램 상자(이미지) 만들기 → 학교 서버로 보내기 → 2장처럼 한 대씩 교체 |

## 용어 한 줄 정리

- **JWT**: 로그인했다는 걸 증명하는 디지털 출입증
- **HttpOnly 쿠키**: 화면의 스크립트가 꺼내 볼 수 없는 쿠키. 출입증을 훔쳐 가기 어렵게 함
- **CSRF**: 다른 사이트가 내 이름으로 몰래 요청을 보내는 공격. 요청마다 확인 표(`X-XSRF-TOKEN`)를 붙여 막음
- **bcrypt**: 비밀번호를 되돌릴 수 없게 바꿔 저장하는 방법
- **jsoup**: 글 속 위험한 HTML을 걸러 내는 도구
- **Docker**: 프로그램과 필요한 것들을 상자 하나에 담아 어디서나 똑같이 켜게 하는 도구
- **GitHub Actions**: 코드가 올라오면 테스트·배포를 자동으로 해 주는 일꾼
- **롤링 배포**: 앱을 한 대씩 차례로 새 버전으로 바꾸는 끊김 없는 배포
