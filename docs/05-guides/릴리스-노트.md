# 릴리스 노트 쓰기

고친 것들을 묶어서 "버전"으로 발표하는 방법입니다. 버전을 만들면 깃허브 **Releases**와 사이트 **공지사항**에 같은 내용이 올라가고, 회원에게 공지 알림이 갑니다 (D-97).

## 평소에 할 일

1. 고칠 거리마다 브랜치를 만들어 고칩니다. `main`은 서버로 자동 배포되므로 직접 고치지 않습니다.
2. 같은 PR에 `CHANGELOG.md` 항목을 한 줄 적습니다 (CLAUDE.md 규칙).
3. PR을 `main`에 합치면 배포가 돌아갑니다.

## 버전을 낼 때

### 1. (보여 줄 화면이 있으면) 노트와 캡처 준비

- 캡처 사진을 `app/src/main/resources/static/img/releases/<버전>/`에 넣습니다. 형식은 png·jpg·gif·webp.
- `docs/releases/<버전>.md`에 노트를 씁니다. 첫 줄 `# 제목`이 공지 제목이 됩니다. 사진은 이렇게 적습니다:

  ```markdown
  ![좋아요 하트](/img/releases/v1.1.0/like-heart.png)
  ```

- 관리자용 내용처럼 깃허브 릴리스에만 적고 사이트 공지에는 넣지 않을 글은 `<!-- github-only -->`와 `<!-- /github-only -->` 사이에 씁니다. 예시: [v1.3.0](../releases/v1.3.0.md)
- 이 두 가지를 PR로 `main`에 합치고 **배포가 끝날 때까지** 기다립니다 (사진이 사이트에 올라가야 공지에 보입니다).
- 노트 파일을 만들지 않으면 `CHANGELOG.md`에서 지난 버전 뒤에 새로 적힌 줄을 모아 노트로 씁니다.

예시: [v1.0.0](../releases/v1.0.0.md)

### 노트 형식 (v1.4.1부터 기본)

앞으로 노트는 [v1.4.1](../releases/v1.4.1.md)처럼 씁니다.

- 맨 위 `# Creat_ <버전> 업데이트 소식`, 바로 아래 한 줄 요약.
- 고친 것마다 `##`(또는 `###`) 제목을 달고 네 칸으로 나눕니다: **무엇이 불편했나요** → **원인** → **어떻게 고쳤나요** → **얼마나 달라졌나요**. 마지막 칸에는 가능하면 고치기 전 → 고친 뒤 숫자(잰 방법이 같은 것)를 적고, 캡처를 붙입니다.
- 회원이 읽는 글이라 쉬운 말로 씁니다. 파일 이름·SQL·설정 키·잰 방법 같은 기술 내용은 `<!-- github-only -->` 안에 둡니다.
- 강조는 사이트 공지가 허용하는 것만 씁니다 (MarkdownRenderer):

  | 쓰는 법 | 사이트 공지 | 깃허브 릴리스 |
  |---|---|---|
  | `> 한 줄` 핵심 정리 | 인용 상자 | 인용 |
  | `**굵게**` | 굵게 | 굵게 |
  | `<u>밑줄</u>` | 밑줄 | `<ins>`로 바꿔 밑줄 |
  | `<span class="hl-yellow">형광펜</span>` (hl-yellow·green·pink·blue) | 형광펜 | `<mark>`로 바꿈 |
  | `<span class="ts-large">큰 글자</span>` (ts-small·large·xlarge) | 글자 크기 | large·xlarge는 굵게, small은 `<sub>` |
  | `<span class="tc-red">글자 색</span>` (tc-*) | 글자 색 | 글자만 남김 |

  깃허브는 class를 지우므로 `.github/scripts/release_notes.py`가 깃허브 글에서만 위처럼 바꿉니다 (D-109). 다른 class나 `style`은 사이트에서 지워집니다.
- 사이트 공지는 5,000자까지라 `<!-- github-only -->` 밖의 글은 짧게 씁니다.
- 실제 화면을 찍을 수 없는 것(예: 카카오 계정 고르기)은 사이트 모양으로 그린 그림에 "안내 그림"이라고 적어 씁니다. 예시 데이터만 쓰고 실제 사람 정보는 넣지 않습니다.

### 2. 버전 만들기 실행

깃허브 저장소 → **Actions** → 왼쪽 **버전 만들기** → **Run workflow** → 버전 이름을 적고 실행.

| 바뀐 것 | 버전 이름 |
|---|---|
| 첫 버전 | `v1.0.0` |
| 기능이 늘었음 | 가운데 숫자 올리기: `v1.0.0` → `v1.1.0` |
| 고치기만 했음 | 끝 숫자 올리기: `v1.1.0` → `v1.1.1` |

끝나면 저장소 오른쪽 **Releases**와 사이트 `/notices`에서 확인합니다. 같은 버전을 다시 돌리면 깃허브 릴리스와 같은 제목의 사이트 공지 내용을 새 노트로 고칩니다 (공지는 두 번 올라가지 않고 알림도 다시 가지 않습니다). 이미 낸 버전의 노트를 고치려면 `docs/releases/<버전>.md`를 고쳐 `main`에 합치고 배포가 끝난 뒤 같은 버전으로 다시 돌립니다. 관리자 페이지 [공지] 탭에서 직접 고쳐도 됩니다.

## 안 될 때

- "RELEASE_NOTICE_TOKEN이 없습니다": 이 기능이 들어간 뒤 배포가 한 번도 안 된 상태입니다. 배포를 한 번 돌린 뒤 다시 실행합니다.
- "사이트에 사진이 아직 없습니다": 캡처가 들어간 `main`이 아직 배포되지 않았습니다. 배포가 끝난 뒤 다시 실행합니다.
