# 릴리스 노트 쓰기

고친 것들을 묶어서 "버전"으로 발표하는 방법입니다. 버전을 만들면 깃허브 **Releases**와 사이트 **공지사항**에 같은 내용이 올라가고, 회원에게 공지 알림이 갑니다 (D-97).

## 평소에 할 일

1. 고칠 거리마다 브랜치를 만들어 고칩니다. `main`은 서버로 자동 배포되므로 직접 고치지 않습니다.
2. 같은 PR에 `CHANGELOG.md` 항목을 한 줄 적습니다 (CLAUDE.md 규칙).
3. PR을 `main`에 합치면 배포가 돌아갑니다.

## 버전을 낼 때

### 1. (보여 줄 화면이 있으면) 노트와 캡처 준비

- 캡처 사진을 `app/src/main/resources/static/img/releases/<버전>/`에 넣습니다. 형식은 png·jpg·gif·webp.
- `docs/releases/<버전>.md`에 노트를 씁니다. 첫 줄 `# 제목`이 공지 제목이 됩니다. 사진은 이렇게 적습니다:

  ```markdown
  ![좋아요 하트](/img/releases/v1.1.0/like-heart.png)
  ```

- 이 두 가지를 PR로 `main`에 합치고 **배포가 끝날 때까지** 기다립니다 (사진이 사이트에 올라가야 공지에 보입니다).
- 노트 파일을 만들지 않으면 `CHANGELOG.md`에서 지난 버전 뒤에 새로 적힌 줄을 모아 노트로 씁니다.

예시: [v1.0.0](../releases/v1.0.0.md)

### 2. 버전 만들기 실행

깃허브 저장소 → **Actions** → 왼쪽 **버전 만들기** → **Run workflow** → 버전 이름을 적고 실행.

| 바뀐 것 | 버전 이름 |
|---|---|
| 첫 버전 | `v1.0.0` |
| 기능이 늘었음 | 가운데 숫자 올리기: `v1.0.0` → `v1.1.0` |
| 고치기만 했음 | 끝 숫자 올리기: `v1.1.0` → `v1.1.1` |

끝나면 저장소 오른쪽 **Releases**와 사이트 `/notices`에서 확인합니다. 같은 버전을 다시 돌리면 깃허브 릴리스 내용만 새로 고치고, 공지는 두 번 올라가지 않습니다. 이미 올라간 공지를 고치려면 관리자 페이지 [공지] 탭에서 고칩니다.

## 안 될 때

- "RELEASE_NOTICE_TOKEN이 없습니다": 이 기능이 들어간 뒤 배포가 한 번도 안 된 상태입니다. 배포를 한 번 돌린 뒤 다시 실행합니다.
- "사이트에 사진이 아직 없습니다": 캡처가 들어간 `main`이 아직 배포되지 않았습니다. 배포가 끝난 뒤 다시 실행합니다.
