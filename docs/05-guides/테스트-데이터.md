# 테스트 데이터

테스트 데이터는 두 가지입니다.

- **실제 사이트(서버)**: 실제 회원은 그대로 두고 테스트 회원 8명과 그 활동을 더하거나 지웁니다. GitHub Actions에서 버튼으로 합니다 → [바로 아래](#실제-사이트에-테스트-회원-넣기-d-113)
- **내 컴퓨터(로컬)**: DB를 통째로 테스트 데이터로 바꿉니다 → [로컬 테스트 데이터](#로컬-테스트-데이터)

## 실제 사이트에 테스트 회원 넣기 (D-113)

테스트 회원은 `members.is_test`로 구분합니다. **숨기지 않고 모두에게 보입니다.** 회원 이름이 보이는 곳(피드, 글, 댓글, 블로그 홈, 프로필, 알림, 관리 화면 등)마다 이름 옆에 작은 "테스트" 표시가 붙습니다. 실제 회원이 테스트 글에 댓글·좋아요를 달거나 테스트 회원을 팔로우해도 됩니다. 관리자 화면 [회원]에서 [전체 · 실제 회원 · 테스트 회원]으로 나눠 볼 수 있습니다.

### 처음 한 번: 비밀번호 시크릿 넣기

GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret

- 이름: `TEST_MEMBER_PASSWORD`
- 값: 테스트 회원 8명이 같이 쓸 비밀번호. 가입 규칙과 같이 8~15자, 영문·숫자·특수문자를 모두 넣습니다
- 비밀번호는 저장소·문서·채팅에 적지 않습니다. 팀원에게는 따로 알려 줍니다
- 나중에 값을 바꾸고 넣기(load)를 다시 돌리면 데이터는 그대로 두고 비밀번호만 바뀝니다

나머지 시크릿(`SSH_*`, `DB_*`)은 배포에 쓰는 것을 그대로 씁니다.

### 넣기 · 지우기

1. 이 기능이 들어간 코드가 main에 합쳐져 **배포까지 끝난 뒤**에 합니다 (서버 이미지에 기능이 없으면 워크플로가 알려 주고 멈춤)
2. GitHub 저장소 → Actions → 왼쪽 **테스트 데이터** → **Run workflow**
3. `action`을 고릅니다
   - `load`: 넣기. 다시 눌러도 더 생기지 않습니다(비밀번호만 시크릿 값으로 맞춤)
   - `remove`: 지우기. 실수로 누르지 않게 `confirm` 칸에도 `remove`라고 적어야 합니다
4. 끝나면 로그 마지막에 `TEST_DATA 결과: ...`가 나옵니다 (넣은·지운 개수)

- 하기 전에 서버 `~/creat-blog/backups/before-test-data-…sql.gz`로 DB를 백업합니다. 지우기는 백업이 안 되면 하지 않습니다
- 운영 중인 앱 두 대는 끄지 않습니다. 같은 이미지로 컨테이너를 하나 더 잠깐 띄워 일만 하고 끝냅니다 (1~3분)
- 배포와 동시에 돌지 않게 배포와 같은 줄에서 기다립니다
- 링크 미리보기 카드는 넣은 뒤 서버가 바깥 사이트(유튜브·비메오 등)를 읽어 만듭니다. 서버가 바깥으로 못 나가면 카드 없이 링크만 보입니다
- 같은 이메일·닉네임·블로그 주소를 실제 회원이 이미 쓰고 있으면 아무것도 넣지 않고 멈춥니다

### 지우기가 지우는 것

- 테스트 회원 8명과 그들의 블로그 5개, 글, 댓글, 좋아요, 조회, 팔로우, 구독, 알림, 신고, 차단, 참여 신청, 블로그 통계 방문 기록, 올린 사진 파일(프로필·머리 사진·글 사진)
- 실제 회원이 테스트 쪽에 남긴 것도 지웁니다: 테스트 글에 단 댓글·좋아요, 테스트 댓글에 단 답글, 테스트 회원 팔로우, 테스트 블로그 구독, 테스트 블로그에 쓴 글, 테스트 회원·글 신고와 그 알림
- 실제 회원, 실제 블로그, 실제 블로그의 실제 글은 지우지 않습니다. 실제 글의 좋아요·댓글 수는 다시 셉니다
- 관리자 작업 기록은 남깁니다

### 넣는 방법

아래 명령과 경로(`scripts/…`, `backups/`, `data/uploads/`)는 모두 소스코드 폴더 `app/` 안에서 실행하는 기준입니다.

```bash
cd app
scripts/test-data/load.sh
```

- 지금 DB를 `backups/blog-날짜.sql`로 먼저 백업한 뒤, **모든 데이터를 지우고** 테스트 데이터로 바꿉니다. 직접 가입해 둔 계정도 사라집니다.
- 되돌리기: `mysql -u blog -p blog < backups/blog-날짜.sql`
- DB 이름·계정이 다르면 `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`로 바꿉니다.
- 서버는 켜 둔 채로 넣어도 됩니다. 넣은 뒤 브라우저에서 다시 로그인하세요.

- `load.sh`가 사진 파일을 서버 업로드 폴더(`UPLOAD_DIR`, 기본 `./data/uploads`)에 복사합니다.
- 2단계 때 이미 테스트 데이터를 넣었다면, 직접 가입한 계정을 지우지 않고 사진만 더할 수 있습니다: `mysql -u blog -p blog < scripts/test-data/add-photos.sql` 후 `cp scripts/test-data/images/* data/uploads/`
- 3단계 기능을 계정들이 써 본 흔적을 남기려면 서버를 띄운 채 `python3 scripts/test-data/activity-3.py`를 한 번 돌립니다. 민수의 [을지로 골목 지도]·공지, 동현의 [망원동 떡볶이 3곳], 지영의 [후쿠오카 1박 2일] 등 글 8개와 카테고리 3개가 생기고, 소연이 동현의 광고 글을 지웁니다. 다시 돌리면 같은 글이 한 번 더 생깁니다.
- 직접 만든 블로그에 테스트 계정들이 참여 신청하게 하려면 `python3 scripts/test-data/join-blog.py 블로그주소` (일부 공개면 공유 키를 뒤에 붙임). 동현·하은·현우·지영·유나가 신청하고, 승인제면 [블로그 관리]에 신청이 쌓입니다.
- 4단계 기능(테마·머리 사진·댓글·좋아요·조회수)을 써 본 흔적은 `python3 scripts/test-data/activity-4.py [서버 주소] [사진 폴더]`로 남깁니다. 블로그장 5명이 자기 블로그에 테마 틀을 고르고(맛집 Magazine, 여행 Whatever, 자바 Letter, 책방 Book Club, 고양이 Poster) 머리 사진을 올리고, 사진 글 9개·댓글과 답글·좋아요·조회가 생깁니다. 사진 폴더(기본 `./data/theme-photos`)에 `cover-foodie.jpg`, `food-tteokbokki.jpg`처럼 이름이 맞는 저작권 걱정 없는 사진(Unsplash·Pexels 라이선스)을 넣어 두면 그 사진을 쓰고, 없으면 `images/`의 테스트 그림으로 대신합니다. 서준은 맛집 블로그에서 정지 중이라 댓글·좋아요가 막히는 것이 맞습니다.
- 큰 사이트처럼 버티는지 보려면 `python3 scripts/test-data/bulk-data.py make`(회원 1,000·글 3만)로 대량 데이터를 넣고, 서버를 띄운 채 `bulk-data.py bench`로 화면별 속도를 잽니다. 이메일 `@bulk.example.com`, 블로그 주소 `bulk-`로 구분되고 `bulk-data.py clean`으로 모두 지웁니다. 테스트 계정(@example.com)은 대량 회원 몇 명을 팔로우하고 블로그 몇 개를 구독해서 피드 탭이 찹니다. DB 접속은 `DB_USERNAME`·`DB_PASSWORD` 환경변수(기본 blog/blog).
- 서울 맛집 탐방: 카테고리 한식·카페, 공지 1개(소연), 강퇴된 재원의 글은 작성자가 "탈퇴한 계정".
- 블로그장(minsu.park)은 남의 글을 지울 수 있고 고칠 수는 없습니다. 부블로그장(soyeon.jung)도 글 관리 권한이 있어 지울 수 있습니다.
