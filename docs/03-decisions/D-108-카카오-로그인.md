# D-108 카카오 로그인

- 날짜: 2026-10-13
- 관련 요구사항: USR-01, USR-03, USR-05, SEC-04, SCL-01, D-99, D-103, D-107
- 선택지:
  1. 카카오만 따로 컨트롤러·테이블을 만든다
  2. 구글(D-103)·네이버(D-107)의 흐름·테이블(`social_accounts.provider`)을 그대로 쓰고, Spring Security OAuth2 Client에 `kakao` 등록만 더한다
- 결정과 이유: 2번. 사용자 요청으로 네이버 다음에 카카오 로그인을 넣는다 (2026-10-13). DB 변경(Flyway)은 없다.
  - 동작은 구글·네이버와 같다: ① 연결된 카카오 계정(`id`)이면 그 회원 ② 카카오 이메일과 같은 이메일의 회원이면 연결하고 로그인 ③ 처음 온 사람은 `/social-signup.html`에서 닉네임·필수 동의 3가지만 받아 가입. 탈퇴하면 연결을 지운다 (USR-05). 로그인 뒤에는 이메일 로그인과 같은 JWT 쿠키
  - 카카오는 스프링 기본 등록이 없어 직접 적는다: authorization `https://kauth.kakao.com/oauth/authorize`, token `https://kauth.kakao.com/oauth/token`, user-info `https://kapi.kakao.com/v2/user/me`, user-name-attribute `id`, `client_secret_post`, `authorization_code`, redirect `{baseUrl}/login/oauth2/code/{registrationId}`
  - scope는 `account_email` 하나만 요청한다. 카카오 콘솔에서 켜지 않은 동의 항목(예: `profile_nickname`)을 요청하면 카카오가 KOE205 오류를 내므로 닉네임·프로필은 받지 않는다. 닉네임은 가입 화면에서 직접 정하고, 이름은 저장하지 않는다
  - 사용자 정보는 `{id: 숫자, kakao_account:{email, is_email_valid, is_email_verified, profile:{nickname}}}`이다. `id`는 숫자라 글자로 바꿔 `provider_user_id`에 저장한다
  - 이메일은 `is_email_valid`와 `is_email_verified`가 모두 true일 때만 쓴다. 이메일이 없거나(동의 안 함) 유효·인증되지 않았으면 가입·연결하지 않고 로그인 화면(`?social=no-email&provider=kakao`)에 "카카오에서 인증된 이메일 제공에 동의해야 가입할 수 있어요."라고 알린다. 인증되지 않은 이메일로 같은 이메일 회원에 연결하면 남의 계정을 가져갈 수 있어서다
  - 실패·거절 안내도 회사 이름을 붙여 보여 준다 (`?social=failed|unverified&provider=kakao`)
  - 가입 화면 이메일 중복 확인(D-99)은 `provider`에 `kakao`를 더하고, 카카오가 연결된 이메일이면 "카카오 계정으로 가입된 이메일입니다. 로그인 화면에서 카카오로 로그인해 주세요."라고 안내한다
  - 앱 값은 환경변수 `KAKAO_CLIENT_ID`(카카오 앱의 REST API 키), `KAKAO_CLIENT_SECRET`으로만 넣는다. 배포 워크플로는 `KAKAO_CLIENT_ID || KAKAO_REST_API_KEY || KAKAO_ID`, `KAKAO_CLIENT_SECRET || KAKAO_SECRET` 순서로 깃허브 시크릿을 읽는다. 비어 있으면 카카오 주소를 열지 않고 로그인 화면의 버튼도 숨긴다. 값은 저장소에 적지 않는다
  - 카카오 개발자 콘솔(developers.kakao.com) 설정:
    1. 앱 → 플랫폼 → Web 사이트 도메인 `https://creat.java21.net` (로컬 시험은 `http://localhost:8080`도 추가)
    2. 카카오 로그인 → 활성화 설정 ON
    3. 카카오 로그인 → Redirect URI `https://creat.java21.net/login/oauth2/code/kakao` (로컬 시험은 `http://localhost:8080/login/oauth2/code/kakao`도 추가)
    4. 동의항목 → 카카오계정(이메일) "필수 동의". 이메일을 필수로 받으려면 비즈 앱(앱 설정 → 비즈니스에서 개인 개발자 비즈 앱 전환)이어야 한다
    5. 앱 키 → REST API 키의 카카오 로그인 항목에서 Client Secret 코드를 만들고 활성화 ON. REST API 키는 `KAKAO_CLIENT_ID`, Client Secret 코드는 `KAKAO_CLIENT_SECRET` 시크릿에 넣는다
  - 버튼은 카카오 로그인 디자인 가이드를 따른다: 배경 `#FEE500`, 말풍선 심볼 `#000000`, 글자 `rgba(0,0,0,0.85)`, 색은 바꾸지 않음(마우스를 올려도 그대로). 심볼과 글자를 가운데로 모으고 사이를 8px 띄운다. 글자는 다른 버튼과 같은 꼴로 "카카오로 로그인". 말풍선 심볼은 화면에 SVG로 직접 넣어 바깥 그림을 받지 않고, 스타일은 `common.css`에만 둔다(CSP). 크기·모서리는 구글·네이버 버튼과 같고 네이버 버튼 바로 아래에 둔다
- 후속 (2026-10-13, 사용자 요청): 로그아웃한 뒤 [카카오로 로그인]을 다시 누르면 카카오에 남아 있는 예전 계정으로 바로 로그인되어, 다른 카카오 계정을 고를 수 없었다. 카카오·구글 로그인 요청에 `prompt=select_account`를 붙여 매번 "어느 계정으로 로그인할까요" 화면을 띄운다. 스프링 기본 처리(`DefaultOAuth2AuthorizationRequestResolver`: state·PKCE·nonce)는 그대로 두고 `SelectAccountRequestResolver`가 `kakao`·`google` 등록에만 이 값을 더한다 (`SecurityConfig`의 `oauth2Login().authorizationEndpoint()`). 네이버는 계정 고르기 화면이 없어 그대로 둔다 — 다른 네이버 계정은 naver.com에서 로그아웃한 뒤 고른다
- 이전 내용 → 바꾼 이유: D-107에서 "카카오는 아직 넣지 않는다" → 사용자 요청으로 카카오를 넣음
