# D-103 구글 로그인

- 날짜: 2026-10-13
- 관련 요구사항: USR-01, USR-03, USR-05, SEC-04, SCL-01, D-53, D-61
- 선택지:
  1. 직접 구현: 구글에서 받은 code를 RestTemplate으로 토큰·프로필과 바꾸고 JWT를 만든다 (사용자가 참고한 velog 글의 방식)
  2. Spring Security OAuth2 Client(`oauth2Login`)에 구글 주고받기를 맡기고, 끝난 뒤에만 우리 JWT 쿠키를 내려준다
- 결정과 이유: 2번. 사용자 요청으로 spec 001에서 "제외"였던 소셜 로그인 중 구글을 먼저 넣는다 (김채림, 2026-10-13). state 확인, ID 토큰 서명 확인 같은 보안 처리를 스프링이 맡아 직접 짜는 코드가 적다.
  - 버튼 주소 `/oauth2/authorization/google` → 구글 → `/login/oauth2/code/google`. 구글 콘솔에는 `https://creat.java21.net/login/oauth2/code/google`과 `http://localhost:8080/login/oauth2/code/google`을 등록한다
  - 찾는 순서: ① `social_accounts`에 연결된 구글 계정(sub)이면 그 회원 ② 구글이 확인한(email_verified) 이메일과 같은 이메일의 회원이면 연결하고 로그인 ③ 처음 온 사람은 `/social-signup.html`에서 닉네임과 필수 동의 3가지만 받아 가입. 이메일 인증은 구글 확인으로 대신한다
  - 이메일이 확인되지 않은 구글 계정은 받지 않는다. 같은 이메일 회원이 이미 다른 구글 계정과 연결돼 있으면 덮어쓰지 않는다
  - 로그인 뒤에는 이메일 로그인과 같은 Access·Refresh 토큰 쿠키(로그인 유지 안 함)를 쓴다. 스프링 세션 로그인은 쓰지 않는다
  - 구글로 보내고 받는 동안만 세션을 잠깐 쓰고 끝나면 지운다. 가입을 마칠 때까지의 구글 정보는 서버에 두지 않고 10분짜리 서명 쿠키(`SOCIAL_SIGNUP`, HttpOnly)에 둔다 (SCL-01)
  - 구글로 가입한 회원의 비밀번호 칸에는 아무도 모르는 값의 bcrypt를 넣는다. 이름은 구글 이름이 이름 규칙에 맞을 때만, 전화번호는 비워 둔다. 비밀번호가 필요하면(탈퇴·비밀번호 변경) 비밀번호 찾기로 새로 정한다
  - 구글이 연결된 회원의 이메일로 일반 가입을 하려 하면 중복 확인과 인증번호 요청에서 "구글 계정으로 가입된 이메일입니다. 로그인 화면에서 구글로 로그인해 주세요."라고 알려 준다. 가입된 이메일인지는 이미 중복 확인으로 알려 주므로(D-99) 구글 여부만 더 알려 준다 (2026-10-13 추가, 사용자 요청)
  - 탈퇴하면 `social_accounts` 연결을 지워 같은 구글 계정으로 새로 가입할 수 있다 (USR-05)
  - 구글 앱 값은 환경변수 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`(깃허브 시크릿)으로만 넣는다. 비어 있으면 구글 주소를 열지 않고 로그인 화면의 버튼도 숨긴다
  - 카카오·네이버는 아직 넣지 않는다 → 네이버는 D-107로 넣음
  - 후속 (2026-10-13): 구글 로그인도 매번 계정 고르기 화면을 띄운다(`prompt=select_account`). 로그아웃한 뒤 다른 구글 계정으로 들어갈 수 있게 (D-108 후속과 같은 처리)
- 이전 내용 → 바꾼 이유: spec 001 범위에서 소셜 로그인은 제외였음 → 사용자 요청
