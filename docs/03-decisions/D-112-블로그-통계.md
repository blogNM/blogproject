# D-112 블로그 통계 (방문자·조회수·들어온 경로)

- 날짜: 2026-10-14
- 관련 요구사항: BLG-05(블로그 관리), BRD-08(검색), BRD-09(피드), BRD-11(조회수), SEC-06, SCL-01, D-77, 추천안 #13
- 선택지:
  1. 블로그 홈·글 화면이 열릴 때 화면 JS가 방문 기록을 한 번 보내고(`POST /api/blogs/{주소}/visits`), 서버가 DB 표 `blog_visits`에 한 줄씩 남긴다. 통계는 볼 때마다 DB에서 모아 센다
  2. 서버가 블로그 홈·글 주소(`/blog/{주소}`, `/blog/{주소}/posts/{번호}`)를 내려 줄 때 기록한다
  3. 구글 애널리틱스 같은 외부 분석 서비스를 붙인다
- 결정과 이유: 1번. 사용자 요청 (김채림, 2026-10-14): "내 블로그 창에서 일별 그래프로 내 블로그 총 조회수(블로그 방문자 수), 일별·달별·시간별로 얼마나 조회됐는지 보기, 내 블로그로 온 경로도 → 검색어 뭘 치고 들어왔는지, 댓글 보고 회원 눌러서 들어왔는지, 피드나 인기글, 블로그 둘러보기에 올라간 거 보고 들어왔는지, 새로 생긴 블로그 눌러서 들어왔는지 블로그를 사용하는 사람이 알 수 있도록". 지금까지는 글마다 조회수(D-77)만 있고 블로그 단위 통계는 없었다.
  - 2번은 화면이 정적 HTML이라 링크에 붙인 표시·이전 화면 주소를 서버가 정확히 알기 어렵고, 카톡 미리보기·검색 로봇이 주소를 열 때도 세게 된다. 화면 JS가 보내면 사람이 실제로 화면을 연 것만 센다
  - 3번은 외부로 방문 정보가 나가고, 블로그별로 나눠 블로그장에게 보여 주기 어렵다
- 무엇을 남기나 (`blog_visits`, Flyway V15)
  - 블로그, 글(블로그 홈이면 비움), 시각(한국 시간), 방문자 값, 들어온 경로, 다른 사이트 주소(호스트만), 검색어
  - **IP 원문은 저장하지 않는다.** 방문자 값 = HMAC-SHA256(서버 비밀 키 `CODE_HASH_SECRET`, `날짜 + IP + 브라우저 정보`). 되돌릴 수 없고, 날이 바뀌면 값이 달라져 다른 날 기록끼리 같은 사람인지도 알 수 없다
  - 서버 메모리에는 아무것도 두지 않는다. 서버 두 대 어느 쪽이 받아도 DB에만 쓴다 (SCL-01, D-111)
- 세지 않는 방문
  - 그 블로그의 블로그장·부블로그장·멤버가 본 것 (자기 블로그를 보는 것은 손님이 아님)
  - 검색 로봇·미리보기 수집기·명령줄 도구 (브라우저 정보에 bot·crawler·spider·preview·headless 등), 브라우저 정보가 없는 요청
  - 볼 수 없는 블로그(비공개·숨김·폐쇄, 공유 키가 틀린 일부 공개)와 그 블로그에 없는 글
  - 같은 사람이 같은 화면(같은 블로그 홈 또는 같은 글)을 **30분 안에** 다시 연 것 (새로 고침). `BLOG_STATS_REPEAT_WINDOW`
  - 블로그 테마 미리보기(`?preview=`)
- 숫자의 뜻
  - **방문자**: 하루에 한 사람을 한 번으로 센 수. 월별·기간 합계는 날마다 센 방문자의 합 (같은 사람이 이틀 오면 2)
  - **조회수**: 블로그 홈·글 화면을 연 수 (위의 세지 않는 방문 제외). 글마다 보이는 조회수(D-77, 하루 한 번)와는 따로 센다. 글 조회수는 블로그 멤버가 본 것도 세기 때문에 두 숫자가 다를 수 있다
  - 시간은 모두 한국 시간
- 들어온 경로 (우리 사이트 링크에는 `?from=`을 붙이고, 화면이 기록을 보낸 뒤 주소창에서 지운다. 표시가 없으면 이전 화면 주소로 가른다)

  | 값 | 화면 이름 | 어떻게 아나 |
  |---|---|---|
  | `search` | Creat_ 검색 | 검색 결과의 글·블로그 링크 `from=search&q=검색어`, 또는 이전 화면이 `/search.html?q=` |
  | `feed` | 피드 최신 글 | 메인 피드 최신 탭 |
  | `popular` | 피드 인기 글 | 메인 피드 인기 탭 |
  | `following` | 팔로우 피드 | 메인 피드 팔로우 탭 |
  | `subscribed` | 구독 피드 | 메인 피드 구독 탭 |
  | `explore` | 블로그 둘러보기 | 메인 블로그 둘러보기 카드 |
  | `new` | 새로 생긴 블로그 | 메인 옆 칸 "새로 생긴 블로그" |
  | `comment` | 댓글 보고 회원 눌러서 | 글 화면에서 댓글 쓴 사람을 눌러 연 프로필 → 그 프로필의 블로그·글 |
  | `profile` | 회원 프로필·활동 | 그 밖의 프로필(글쓴이·팔로워 목록 등)에서 누른 블로그·글, 또는 이전 화면이 `/members/` |
  | `notification` | 알림 | 블로그·글로 가는 알림 |
  | `site` | Creat_ 다른 화면 | 표시 없이 우리 사이트의 다른 화면에서 옴 (내 블로그 목록 등) |
  | `external` | 다른 사이트 | 이전 화면이 다른 사이트. 호스트만 저장(`www.` 뺌), 주소에 `q`·`query`·`wd`·`search_query`·`keyword`가 있으면 검색어도 |
  | `direct` | 직접 들어옴 | 이전 화면이 없음: 주소 입력, 즐겨찾기, 메신저·앱에서 연 링크, 글 본문 속 링크(본문 링크는 `noreferrer`) |
  | `inside` | 블로그 안에서 이동 | 이전 화면이 같은 블로그. 들어온 경로가 아니라서 경로 목록에서는 빼고 따로 개수만 보인다 |

  - 검색어는 앞뒤 공백을 지우고 공백을 하나로, 영문은 소문자로, 30자까지(`BLOG_STATS_KEYWORD_MAX`). 글자·숫자가 없으면 버린다
  - 구글 등 대부분의 검색 사이트는 주소에서 검색어를 지워 보내므로, 다른 사이트 검색어는 남지 않는 경우가 많다
- 누가 보나: 블로그 관리 화면에 들어오는 블로그장·부블로그장(받은 권한과 상관없이) (`@blogAuth.canViewStats`). 일반 멤버·다른 회원·비회원은 못 본다. 블로그 홈에도 블로그장·부블로그장에게 [통계] 버튼이 생겨 관리 화면의 통계로 바로 간다
- 화면 (관리 화면 맨 위 "블로그 통계")
  - 오늘·어제·최근 30일·전체(보관 기간) 방문자와 조회수
  - [시간별](고른 날 0~23시) · [일별](최근 7·14·30·90일, 끝 날 고르기) · [월별](최근 12달) 그래프. 방문자는 막대, 조회수는 선. 칸에 마우스를 올리거나 누르면 값이 보이고, [표로 보기]에 같은 값이 있다
  - 고른 기간의 들어온 경로(횟수·비율 막대), 검색어 순위, 다른 사이트 순위, 많이 본 글
  - 그래프는 외부 라이브러리 없이 SVG로 그리고, 검색어·글 제목·사이트 이름은 모두 `textContent` (SEC-06)
- 보관: 400일(`BLOG_STATS_RETENTION_DAYS`). 1년 전 같은 달과 견줄 수 있게. 매일 04:20 새벽 정리 작업이 지난 기록을 5,000줄씩 나눠 지운다 (app-a에서만, ShedLock, D-111). 블로그가 폐쇄 30일 뒤 완전히 지워질 때 그 블로그의 기록도 지운다
- 설정 (`blog.stats.*`): `retention-days` 400, `repeat-window` 30m, `keyword-max` 30, `max-day-range` 92, `top-count` 10
- 이전 내용 → 바꾼 이유: 블로그 통계가 없었음(글 조회수만, D-77) → 블로그를 운영하는 사람이 방문자와 들어온 경로를 알 수 있게 (사용자 요청)

- 2026-10-14: 개인정보처리방침(`privacy.html`)에 "블로그 통계" 항목을 넣음 (김채림 결정). 통계는 블로그장·부블로그장만 보고, 통계 조회수는 30분 안에 다시 연 화면을 한 번으로 세는 것으로 확정.
- 2026-10-15: 개인정보 처리방침 전체를 김채림님 초안(13개 항목)으로 바꾸고, 블로그 방문 기록을 항목·목적·보유 기간 표에 넣음. 통계 볼 사람(블로그장·부블로그장)과 30분 기준은 다시 확인함 (김채림 결정)
