# D-97 릴리스 노트를 사이트 공지로

- 날짜: 2026-10-12
- 관련 요구사항: BRD-10, SOC-04, SCL-01, SEC-08
- 선택지: (사용자 요청이라 선택지 없음) 공지를 올리는 길만 골랐다
  1. 깃허브 Actions가 바깥 주소로 관리자 로그인을 해서 공지를 쓴다 → 관리자 비밀번호를 깃허브에 둬야 하고, 첫 로그인 비밀번호 바꾸기·보안문자에 막힘
  2. 서버에 SSH로 들어가 DB에 바로 넣는다 → 알림·관리자 기록을 따로 다시 만들어야 함
  3. 앱에 릴리스 공지 주소를 하나 두고, 서버 안에서만 아는 토큰으로 부른다 → 고름
- 결정과 이유: 깃허브에서 버전(릴리스)을 만들면 같은 내용이 메인 공지사항에도 올라가게 한다. 보여 줄 화면이 있으면 캡처 사진을 넣고, 첫 버전은 v1.0.0 (김채림, 2026-10-12).
  - 버전 이름은 `v주.부.수` (v1.0.0부터). 기능이 늘면 가운데, 고치기만 했으면 끝 숫자를 올린다
  - 노트는 `docs/releases/<버전>.md`가 있으면 그 글, 없으면 CHANGELOG.md에서 지난 버전 뒤에 새로 적힌 줄
  - 캡처는 `app/src/main/resources/static/img/releases/<버전>/`에 넣어 앱과 함께 배포한다. 글 본문 사진 규칙(이 사이트 사진만, CSP `img-src 'self'`)에 `/img/releases/`를 더함. 깃허브 릴리스에는 같은 사진을 깃허브 주소로 바꿔 넣는다
  - `POST /api/release-notices`: `X-Release-Token`이 서버 `secrets.env`의 `RELEASE_NOTICE_TOKEN`과 같아야 한다. 값이 없으면 404. 브라우저가 부르지 않으므로 CSRF 검사에서 뺀다
  - 작성자는 가장 먼저 만든 관리자. 보통 공지처럼 회원에게 알림이 간다. 같은 제목의 공지가 있으면 새로 쓰지 않는다 (다시 돌려도 알림 한 번)
  - 공지 본문은 5000자까지라 길면 자르고 깃허브 릴리스 링크를 붙인다
