# D-113 테스트 회원 (실제 사이트에 넣고 지우기)

- 날짜: 2026-10-14
- 관련 요구사항: USR-01(회원가입), ADM(회원 관리), BLG-05, D-85, D-89, D-92, D-110, D-111, D-112, SEC-06, SEC-08, SCL-01
- 선택지:
  1. 같은 DB의 `members`에 테스트 회원 표시(`is_test`)를 두고, 테스트 회원과 그 활동을 앱 코드로 넣고 지운다
  2. 테스트 회원만 담는 DB를 따로 만든다
  3. 로컬처럼 `scripts/test-data/load.sh`로 DB를 통째로 바꾼다
- 결정과 이유: 1번. 사용자 요청 (김채림, 2026-10-14): "로컬 사이트 말고 도메인 인증된 사이트에 테스트 계정을 넣을 수 있나? 블로그 통계랑 여러 기능들이 잘 작동하는지 보고싶어. 테스트 계정만 따로 관리하는 db를 만들어서 회원과 테스트 회원만 따로 볼 수 있게 가능할까?"
  - 2번은 앱 하나가 DB 두 개를 오가야 해서 글·댓글·팔로우가 실제 회원과 이어지지 않고, 실제 사이트에서 기능을 보는 뜻이 없어진다
  - 3번은 실제 회원 데이터가 모두 지워진다
- 무엇이 바뀌나
  - `members.is_test` (Flyway V16, 기본 FALSE). 가입·소셜 로그인으로 생긴 회원은 언제나 실제 회원이다. 화면이나 API로 바꿀 수 없다 (실제 회원을 테스트로 바꾸면 지우기 때 함께 지워지므로 관리자 전환 기능도 두지 않음)
  - **테스트 데이터는 모두에게 그대로 보인다.** 피드·검색·블로그 둘러보기·통계 어디에서도 숨기지 않고, 실제 회원이 테스트 글에 댓글·좋아요를 달거나 테스트 회원을 팔로우하는 것도 막지 않는다 (김채림 결정, 2026-10-14)
  - 회원 이름이 보이는 곳마다 이름 옆에 작은 **"테스트"** 표시를 붙인다: 피드·글 목록 카드, 글 화면 글쓴이·댓글, 블로그 홈·블로그 카드의 블로그장, 프로필·팔로워 목록, 알림, 위쪽 메뉴의 내 닉네임, 차단 목록, 블로그 관리의 참여 신청·멤버·신고, 관리자 화면. 표시는 `js/test-badge.js` 한 곳에서 `textContent`로 만든다 (SEC-06). API 응답에는 `authorTest`·`ownerTest`·`actorTest`·`test` 값이 붙는다
  - 관리자 회원 목록에 [전체 · 실제 회원 · 테스트 회원] 거르기와 개수 (`GET /api/admin/members?kind=all|real|test`). 검색어를 넣으면 개수도 그 검색 결과로 센다
- 넣기 (`load`)
  - 앱 자신이 `TEST_DATA_ACTION=load`로 한 번 떠서 넣고 끝난다 (`testdata` 패키지). 실제 서비스 코드(가입 규칙, 블로그 만들기, 글쓰기, 사진 올리기, 댓글, 신고, 제재 등)를 그대로 불러서 넣으므로 실제 사용과 같은 모양이 된다. 날짜를 몇 주 전으로 옮기는 것과 통계용 방문 기록만 SQL로 넣는다
  - 사진은 앱에 들어 있는 직접 만든 그림(`resources/test-data/images/`)을 실제 업로드 경로(확장자·MIME·시그니처 검사, SEC-08)로 올린다
  - 테스트 회원 8명, 블로그 5개(테마 틀 5가지, D-89), 글 18개(사진·유튜브·비메오·링크 미리보기 카드 D-92, 체크박스·글자 크기 D-110, 표·코드, 공지, 본문 1000자 꽉 찬 글), 댓글·답글, 좋아요, 조회, 팔로우·구독, 여러 사유의 신고(블로그장 접수와 관리자 접수, D-85), 경고 제재, 부블로그장 권한 세 가지, 참여 신청 대기·승인·거절, 블로그장 위임 대기, 차단, 알림 설정, 공개 범위 설정, 6주치 방문 기록(D-112)
  - 이메일은 `test1@test.creat` ~ `test8@test.creat` (메일이 가지 않는 주소), 닉네임은 `테스트…`, 블로그 주소는 `test-…`
  - 비밀번호는 저장소에 두지 않고 GitHub 시크릿 `TEST_MEMBER_PASSWORD`로만 받는다. bcrypt로 저장한다
  - 다시 돌려도 더 생기지 않는다. 이미 있으면 비밀번호만 시크릿 값으로 바꾼다. 같은 이메일·닉네임·블로그 주소를 실제 회원이 쓰고 있으면 아무것도 넣지 않고 멈춘다
  - 링크 미리보기 카드는 넣은 뒤 바깥 사이트를 읽어 만든다(서버가 바깥으로 나갈 수 있어야 함). 실패해도 글은 남는다
- 지우기 (`remove`): 한 트랜잭션에서 테스트 데이터 **모두**를 지운다
  - 테스트 회원, 그들의 블로그와 그 블로그의 모든 글(블로그에 들어온 실제 회원이 쓴 글도 블로그와 함께 지워짐), 테스트 회원이 쓴 글·댓글·좋아요·조회·팔로우·구독·알림·신고·차단·참여 신청·방문 기록·올린 사진 파일
  - 실제 회원이 테스트 콘텐츠에 남긴 것: 테스트 글의 댓글·좋아요, 테스트 댓글에 단 답글, 테스트 회원 팔로우, 테스트 블로그 구독, 테스트 대상 신고와 그 알림
  - 실제 회원·실제 블로그·실제 블로그의 실제 글은 지우지 않는다. 실제 글의 좋아요·댓글 수는 다시 센다. 마지막 회원 삭제는 `is_test = TRUE`인 줄만 지운다
  - 관리자 작업 기록(`admin_action_logs`)은 감사 기록이라 남긴다
- 실행: GitHub Actions의 [테스트 데이터] 워크플로(수동 실행, load/remove). 서버에서 지금 이미지로 컨테이너를 하나 더 잠깐 띄워 일만 하고 끝낸다. 운영 중인 앱 두 대는 건드리지 않고 서버 메모리에도 아무것도 남기지 않는다 (SCL-01, D-111). 하기 전에 DB를 백업하고, 지우기는 백업이 안 되면 멈춘다. 방법은 [테스트-데이터.md](../05-guides/테스트-데이터.md)
- 설정 (`test-data.*`): `TEST_DATA_ACTION`(비우면 평소처럼 앱이 뜸), `TEST_MEMBER_PASSWORD`, `TEST_DATA_LINK_PREVIEWS`(기본 true)
- 이전 내용 → 바꾼 이유: 테스트 계정은 로컬 DB를 통째로 바꾸는 방법만 있었음 → 실제 회원 데이터를 두고 실제 사이트에서 통계 등 여러 기능을 볼 수 있게 (사용자 요청)
