# D-124 링크 미리보기는 글 저장 뒤에 따로 받는다

- 날짜: 2026-10-15
- 관련 요구사항: D-92(링크 미리보기 카드), SCL-01(서버 메모리에 상태 두지 않기)
- 사용자 요청 (김채림, 2026-10-15): "링크가 든 글은 저장이 오래 걸림"
- 고치기 전: 글을 저장하면 서버가 글 속 링크(최대 5개)의 페이지와 썸네일을 그 자리에서 받은 뒤에야 응답했다. 링크 하나에 3초까지 기다려서 링크가 많거나 바깥 사이트가 느리면 저장 버튼이 몇 초씩 멈춰 있었다
- 결정
  - 글 저장 응답은 미리보기를 기다리지 않는다. 미리보기는 저장이 끝난 뒤 스프링 기본 작업 스레드(`applicationTaskExecutor`)에서 받는다
  - 받는 동안 글을 열면 그 링크는 원래 글자 링크로 보이고, 다 받은 뒤 다시 열면 카드로 보인다
  - 받는 도중 서버가 꺼지면 그 미리보기만 빠진다. 받은 결과는 DB(`link_previews`)에만 두므로 두 서버 어느 쪽이 받아도 같다 (SCL-01). 빠진 미리보기는 글을 다시 저장하면 다시 받는다
  - 설정 `link-preview.background`(`LINK_PREVIEW_BACKGROUND`, 기본 true). 테스트는 false로 두어 저장한 뒤 바로 카드를 확인한다
- 고르지 않은 것
  - 기다리는 시간(3초)이나 링크 수(5개)만 줄이기: 느린 사이트가 하나라도 있으면 여전히 저장이 늦어지고, 카드가 덜 생긴다
  - 글을 읽을 때 받기: 첫 독자가 기다리게 되고, 바깥 사이트에 독자마다 요청이 갈 수 있다 (D-92에서 하지 않기로 함)
