# D-129 매일 백업과 서버 밖 보관

- 날짜: 2026-11-18
- 관련 요구사항: SCL-01, D-111, D-128
- 사용자 요청 (김채림, 2026-11-18): "블로그에서 보강해야 할점 알려줘봐" → "하나씩 해결하자". 점검 1번(매일 백업이 없음)부터
- 배경: D-128로 배포할 때와 DB를 지우기 전에는 DB를 백업하지만, 매일 뜨는 백업이 없고 그 파일도 같은 서버 디스크에 있다. 올린 사진(`data/uploads`)은 백업하지 않는다. 서버 디스크가 망가지면 둘 다 잃는다
- 결정
  1. **매일 새벽 5:10(한국 시간)** GitHub Actions 워크플로 "매일 백업"(`.github/workflows/backup.yml`)이 SSH로 서버에 들어가 `app/deploy/backup.sh`를 돌린다. 새벽 정리 작업(04:00~04:20) 뒤
  2. 서버에서 DB를 `~/creat-blog/backups/daily-*.sql.gz`로 뜨고, 덤프 끝의 "Dump completed" 줄과 gzip이 온전한지 확인한다. 서버에는 최근 14개(`BACKUP_KEEP_DAILY`)만 남긴다. 배포 때 뜬 `before-*`는 따로 14개(`BACKUP_KEEP`)를 센다
  3. **서버 밖 보관은 이 저장소의 Actions 보관함(아티팩트)**. 따로 계정·키를 만들 것이 없고 지금 배포와 같은 SSH 시크릿을 쓴다. 보관 14일(`BACKUP_RETENTION_DAYS`, 1~90)
  4. 올린 사진은 **일요일**과 손으로 돌릴 때만 함께 가져간다. 사진은 날마다 크게 바뀌지 않고, 깃허브 무료 저장 용량(비공개 저장소 약 500MB)을 아끼려고
  5. `BACKUP_PASSWORD` 시크릿을 넣으면 받아 온 파일을 gpg AES256으로 암호화해서 올린다. 넣지 않으면 저장소를 볼 수 있는 사람만 받을 수 있는 상태로 둔다
  6. 받는 법·되돌리는 법은 `docs/05-guides/백업-복구.md`
- 고르지 않은 것
  - 구글 드라이브 등 클라우드 보관: 계정·키 준비가 필요하다. 사진이 많아져 용량이 모자라면 다시 정한다
  - 사용자 Mac으로 받기: Mac이 꺼져 있으면 그날 백업이 서버에만 남는다
  - 사진을 바뀐 것만 받기(증분): 지금 크기에서는 통째로 받는 것이 단순하다
