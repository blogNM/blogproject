# D-110 체크박스 목록과 굵어지지 않는 글자 크기

- 날짜: 2026-10-14
- 관련 요구사항: BRD-01, BRD-10, SEC-06, D-64, D-102, D-106
- 선택지:
  1. 글자 크기 class(`ts-*`)는 크기만 바꾸고, 편집기 목록 도구에 체크박스 목록(Toast UI `task`)을 더한다. 서버는 commonmark 체크박스 목록 확장으로 `<input type="checkbox" disabled>`를 만들고 jsoup이 그 모양만 남긴다
  2. 크기는 그대로 두고 체크박스를 `☐`·`☑` 글자로 넣는다
  3. 체크박스를 정해 둔 class의 span(`<span class="task-on">`)으로 넣는다
- 결정과 이유: 1번. 사용자 요청 (김채림, 2026-10-14): "글자 크기를 크게하면 강제로 글씨가 두껍게 되는 효과가 적용되는것과, 글 작성에 체크박스와 글머리 기호 목록(bullet list)을 추가해서 정보를 깔끔하고 읽기 쉽게 하는 기능을 추가". 굵게는 [B]로 따로 고를 수 있으므로 크기가 굵기까지 정하면 "크지만 보통 굵기"를 쓸 수 없다. 체크박스 목록은 GFM 표준 문법(`- [ ]`)이라 깃허브 릴리스에서도 그대로 보이고, Toast UI가 이미 도구를 갖고 있다. 2번은 글자 수에 들어가고 정렬이 맞지 않으며, 3번은 새 문법을 만들어야 한다.
  - **글자 크기**: `.ts-xlarge`의 `font-weight: 700`을 뺀다(작게·크게는 원래 굵기를 바꾸지 않았음). 이미 쓴 글·공지에서 "아주 크게"로 쓴 글자는 보통 굵기로 보인다. 굵게 보이려면 [B]를 함께 고른다. 깃허브 릴리스는 글자 크기를 못 쓰므로 `release_notes.py`가 지금처럼 `ts-large·xlarge`를 굵게로 바꾼다(깃허브에서만, D-109)
  - **목록 도구**: 도구 막대 목록 칸이 글머리 기호 목록·번호 목록·체크박스 목록 세 개가 된다. 회원 글쓰기와 관리자 공지 쓰기가 같은 편집기(`rich-editor.js`)라 둘 다 생긴다. 쓰는 칸에서 네모를 누르면 체크·해제된다
  - **도구 순서**: 꾸미기(굵게~크기) 바로 뒤에 목록 세 개를 두고, 제목·구분선·인용은 그 뒤로 옮긴다. [HTML 보기]로 편집 칸이 좁아지면 버튼 사이를 줄여 목록 도구가 [⋯] 안으로 숨지 않게 한다
  - **저장 형식**: 글머리 목록은 `- 항목`, 체크박스 목록은 `- [ ] 할 일`·`- [x] 한 일`. Toast UI 기본은 `* `라 편집기가 `- `로 쓰게 바꾼다(예전 `* ` 글도 그대로 읽히고, 다시 저장하면 `- `가 된다. 보이는 모양은 같음)
  - **글 화면**: 서버가 `commonmark-ext-task-list-items`로 바꾸고, jsoup은 `input` 중 목록 줄(`li`) 맨 앞의 `type="checkbox"`만 남긴다. 속성은 `type`·`checked`만 받고 `disabled`를 항상 붙이며, 그 `li`에 `class="task-list-item"`을 붙인다. 다른 input(text·password 등)이나 다른 자리의 checkbox, `name`·`onclick` 같은 속성은 지운다. 보는 사람은 체크를 바꿀 수 없다(글을 고쳐야 바뀜). 화면은 글머리 점 없이 보라색 네모(체크하면 흰 체크 표시)로 보이고, 체크한 줄도 줄을 긋거나 흐리게 하지 않는다
  - **HTML 보기**: 체크박스 줄을 글 화면과 같은 `<li class="task-list-item"><input type="checkbox" checked disabled> …</li>` 모양으로 보여 준다
  - **글자 수(1000자)**: 색·크기·형광펜 span 표시를 빼는 것처럼, 목록 줄 맨 앞의 `[ ] `·`[x] `도 세지 않는다. 글머리 목록과 같게 `- `까지만 센다(PostRules, rules.js)
- 이전 내용 → 바꾼 이유: "아주 크게"는 굵게가 함께 걸렸고(D-102), 목록은 글머리·번호뿐이었음 → 크기와 굵기를 따로 고르고, 할 일·준비물처럼 체크하는 목록을 깔끔하게 쓰게 (사용자 요청)
