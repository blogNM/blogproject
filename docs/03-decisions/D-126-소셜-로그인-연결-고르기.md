# D-126 소셜 로그인으로 처음 오면 연결·가입을 먼저 고르기

- 날짜: 2026-10-16
- 관련 요구사항: USR-01, USR-03, USR-06, SEC-03, SEC-13, D-103, D-107, D-108
- 사용자 요청 (김채림, 2026-10-16): "구글, 카카오톡, 네이버로 로그인 하면 원래 있는 계정이랑 연동할지.. 아니면 비번 만들어서 소셜 로그인 할지 먼저 고르는 창이 나오도록하자. 비번찾는 시스템을 소셜 로그인 사용하는 사람은 못쓰니까 쓸 수 있게끔"
- 고치기 전: 처음 온 사람은 닉네임·약관 동의만 받아 바로 가입했다. 비밀번호 칸에는 아무도 모르는 값을 넣어, 이메일 로그인을 못 하고 비밀번호 찾기를 써야 하는지도 알 수 없었다. 이메일이 다른 기존 계정에는 연결할 방법이 없었다
- 결정
  - 구글·네이버·카카오에서 처음 돌아오면 `/social-signup.html`에서 먼저 고른다: **이미 Creat_ 계정이 있어요**(연결) / **처음이에요, 새로 가입할게요**(가입)
  - **연결**: 연결할 계정의 이메일·비밀번호를 받아 로그인과 똑같이 확인한다(같은 요청 수 제한, 3번 틀리면 사람 확인, 5번 잠금). 맞으면 그 회원에 소셜 계정을 연결하고 로그인한다. `POST /api/auth/social/link`
    - 그 회원에 같은 회사의 다른 계정이 이미 연결돼 있으면 덮어쓰지 않는다(`PROVIDER_TAKEN`)
    - 비밀번호를 모르면 비밀번호 찾기로 새로 정한 뒤 다시 하도록 안내한다
  - **가입**: 닉네임·약관 동의에 더해 **비밀번호(8~15자, 영문·숫자·특수문자)를 꼭 정한다**. 소셜 계정의 이메일과 이 비밀번호로 이메일 로그인도 되고, 비밀번호 찾기도 그대로 쓴다
  - 소셜 계정 이메일과 같은 이메일의 회원이 이미 있으면 지금처럼 고르는 화면 없이 바로 연결한다. 그 회사가 이메일을 확인해 주므로 이메일 확인으로 본다 (D-103)
  - 이미 가입한 소셜 회원(비밀번호를 정하지 않은 회원)은 비밀번호 찾기에서 가입 이메일로 비밀번호를 정할 수 있다. 비밀번호 찾기 화면에 안내 한 줄을 넣는다
- 이전 내용 → 바꾼 이유: D-103의 "비밀번호는 아무도 모르는 값, 필요하면 비밀번호 찾기" → 사용자 요청
