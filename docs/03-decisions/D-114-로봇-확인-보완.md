# D-114 로봇 확인(Turnstile) 실제 키와 보완

- 날짜: 2026-10-14
- 관련 요구사항: SEC-03(로그인 잠금), SEC-13(사람 확인), ADM-01(관리자 로그인), D-79, D-80, D-84, SCL-01
- 사용자 요청 (김채림, 2026-10-14): "로봇 확인 상자가 항상 통과되는 문제(테스트키에서는 이럼) → Cloudflare 무료 키 넣어줘, 그리고 여러번 틀려도 캡챠 안나오던데 그것도 보완해주고"
- 원인
  1. 실제 사이트에 `TURNSTILE_SITE_KEY`·`TURNSTILE_SECRET_KEY`가 없어서 Cloudflare가 공개한 "늘 통과" 테스트 키로 돌고 있었다. 테스트 키는 누구나 통과한다
  2. 실패를 **이메일마다**만 셌다. 이메일을 바꿔 가며 틀리면(오타, 다른 계정 맞혀 보기) 몇 번을 틀려도 상자가 나오지 않았다
  3. **관리자 로그인**에는 사람 확인도 잠금도 없었다. 서버 메모리의 1분 요청 제한(D-80, 서버마다 따로 셈)만 있었다
  4. Cloudflare 스크립트를 못 받으면(광고 차단, 네트워크) 빈 칸만 생기고 아무 안내가 없었다
- 선택지
  1. IP별 실패도 DB에 세서 사람 확인을 띄우고, 관리자 로그인에도 회원과 같은 규칙을 둔다 → 고름
  2. 모든 로그인에 처음부터 사람 확인을 띄운다 → 매번 한 번 더 눌러야 해서 불편하고 D-79(3번 실패 뒤)와 다름
  3. IP별로 잠근다 → 학교처럼 한 IP를 여럿이 쓰면 다른 사람까지 막힌다
- 결정
  - 계정(회원 이메일·관리자 아이디)마다 **3번 틀리면 사람 확인, 5번이면 5분 잠금**. 관리자도 같다 (`LOGIN_CAPTCHA_AFTER`, `LOGIN_LOCK_AFTER`, `LOGIN_LOCK_DURATION`)
  - 같은 IP에서 계정을 바꿔 가며 **1시간 안에 5번** 틀리면 그 IP의 로그인에 사람 확인을 띄운다 (`LOGIN_CAPTCHA_AFTER_IP`, `LOGIN_IP_WINDOW`). IP로는 잠그지 않는다. 로그인에 성공해도 IP 수는 지우지 않는다(내 계정으로 한 번 들어와 수를 지우고 다시 맞혀 보지 못하게)
  - 세는 곳은 기존 `login_failures` 한 표. 회원은 이메일, 관리자는 `admin:아이디`, IP는 `ip:주소`로 적는다. 이메일에는 늘 @가 있어 겹치지 않는다 (Flyway V17은 설명만 고침). 서버 두 대가 같은 수를 본다 (SCL-01). IP 수는 한 문장(`INSERT … ON DUPLICATE KEY UPDATE`)으로 올려 동시에 틀려도 엇갈리지 않는다. 하루 지난 줄은 기존 새벽 정리 작업이 지운다
  - 화면: 사람 확인 상자 코드를 `js/turnstile.js` 한 곳으로 모아 회원·관리자 로그인이 같이 쓴다. 상자를 못 불러오면 "로봇 확인 상자를 불러오지 못했어요…"를 보여 주고, 상자가 보이도록 스크롤한다
  - 실제 키: 코드는 이미 `TURNSTILE_SITE_KEY`·`TURNSTILE_SECRET_KEY`를 GitHub Actions secrets → `deploy.sh` → `secrets.env`로 받는다. 키는 사용자 Cloudflare 계정에서 만들어 secrets에 넣는다 (값은 저장소·문서·채팅에 적지 않음). 테스트 키로 뜨면 서버 로그에 경고를 남긴다. 만드는 법은 [도커-배포.md](../05-guides/도커-배포.md#로봇-확인-실제-키-넣기-d-114)
