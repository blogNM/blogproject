# D-132 사진 흘려보내기, 쓰지 않는 링크 미리보기 정리, 테스트 보강, DB 구조 바꾸기 규칙

- 날짜: 2026-11-18
- 관련 요구사항: BRD-05, SEC-08, SCL-01, D-80, D-92, D-111, D-128
- 사용자 요청 (김채림, 2026-11-18): "블로그에서 보강해야 할점 알려줘봐" → "하나씩 해결하자" → "2번 제외하고 하자". 점검 11·12·17·18번
- 결정
  1. **사진 내려 보내기**: `/uploads/{UUID}`는 파일을 통째로 메모리에 읽지 않고 조금씩 흘려 보낸다(힙 512MB). 같은 이름의 내용은 바뀌지 않으므로 `Cache-Control: max-age=1년, immutable`과 `ETag`를 주고, 다시 물으면 304만 돌려준다
     - Nginx가 `/uploads`를 바로 내보내는 방법은 고르지 않았다. 파일에 확장자가 없어 형식(Content-Type)을 DB에서 읽어야 하고, 보안 헤더(nosniff·CSP)를 Nginx에도 따로 맞춰야 하며, 우리 Nginx 컨테이너를 다시 만들어야 해서 지금 크기에서는 얻는 것보다 위험이 크다. 사진이 많아지면 다시 본다
  2. **쓰지 않는 링크 미리보기 정리**: 받은 지 30일(`LINK_PREVIEW_UNUSED_KEEP`)이 지났고 어느 글(지운 글 포함)에도 그 주소가 없는 미리보기는 새벽 4시 글 정리 작업이 지운다. 썸네일은 글에 붙지 않은 사진이 되어 같은 작업에서 파일까지 지워진다. 한 번에 500개씩
  3. **테스트 보강**: 요청 제한기(횟수·창·동시 200번·끝난 창 치우기), 링크 미리보기 시간 상한(본문을 천천히 보내는 사이트), 닫힌 블로그 완전 삭제(글·댓글·좋아요·사진 행과 지울 파일 이름, 다른 블로그는 그대로), 쓰지 않는 미리보기 정리, 사진 304
  4. **DB 구조 바꾸기 규칙**: 롤링 배포 중에는 옛 앱이 새 DB 구조로 돌아가므로 "늘리고 → 나중에 줄이기"로 나눈다. `docs/05-guides/DB-마이그레이션-규칙.md`
