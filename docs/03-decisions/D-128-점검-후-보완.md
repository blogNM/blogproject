# D-128 점검 뒤 보완 (인증번호 동시 요청, 링크 미리보기, 백업, PR 테스트 등)

- 날짜: 2026-10-16
- 관련 요구사항: USR-02, USR-06, SOC-08, BRD-05, BRD-06, BRD-11, SEC-08, D-77, D-92, D-111, D-127
- 사용자 요청 (김채림, 2026-10-16): "이 블로그의 취약점은 뭐고, 보완해야 할 점은 뭔지 찾아서 알려줘봐." → "보완할 수 있는 것부터 보완해서 알려줘"
- 점검 결과는 프로젝트 파일 `notes/취약점-보완점-점검-2026-10-16.md`. 그 가운데 정할 것 없이 바로 고칠 수 있는 것을 고친다
- 결정
  1. **인증번호 틀린 횟수 잠그고 세기**: 가입·비밀번호 찾기 인증번호를 맞혀 볼 때 행을 잠그고(`SELECT … FOR UPDATE`) 읽는다. 잠그지 않으면 수백 개를 한꺼번에 보낼 때 모두 "0번 틀림"으로 읽혀 5번 제한을 넘어 6자리를 맞힐 수 있었다. 로그인 실패 횟수(`LoginFailureRepository`)와 같은 방식
  2. **인증번호 메일은 저장이 끝난 뒤에**: DB 저장이 실패하면 메일도 보내지 않는다 (저장 안 된 번호가 메일로 가지 않게)
  3. **링크 미리보기**
     - 한 번 요청은 응답 머리와 본문을 합쳐 `LINK_PREVIEW_TIMEOUT`(3초) 안에 끝나야 한다. 본문을 아주 천천히 보내는 사이트가 서버 일꾼을 몇 분씩 붙잡지 못한다
     - 글 하나를 저장할 때 미리보기 받기에 쓰는 시간을 모두 합쳐 `LINK_PREVIEW_COLLECT_BUDGET`(8초)까지. 넘으면 남은 링크는 카드 없이 두고 다음 저장 때 받는다
     - 바깥 주소는 **https로만** 받는다. http 링크는 https로 바꿔 받아 보고, https가 안 되는 사이트는 카드 없이 글자 링크로 둔다. 검사할 때와 접속할 때 DNS 답을 바꿔 내부망으로 돌리는 공격(DNS rebinding)은 공격자 도메인 인증서가 내부 서버에 있을 수 없어 연결 단계에서 끊긴다. D-127에서 미뤘던 "한 번 푼 IP로만 접속"을 인증서 확인을 바꾸지 않고 대신하는 방법
     - 썸네일도 글쓴이가 올린 사진으로 센다(`RATE_UPLOAD_PER_MINUTE`, D-127). 넘으면 썸네일 없이 카드만 둔다
  4. **사진 가로×세로 상한**: 파일 머리에서 가로·세로만 읽어(그림은 풀지 않음) 5000만 화소(`UPLOAD_MAX_PIXELS`)를 넘으면 받지 않는다(`IMAGE_TOO_BIG`). 3MB짜리 30000×30000 사진이 읽는 사람 브라우저를 멈추게 하지 못한다. 썸네일도 같다
  5. **본문 사진 주소 모양 전체 확인**: `/uploads/{UUID}`, `/img/releases/…`, `/img/guides/…` 파일 모양만 받는다. 앞부분만 보던 때는 `/uploads/../api/posts/1`처럼 다른 주소를 읽는 사람마다 부르게 해 조회수·최근 검색어를 바꿀 수 있었다
  6. **관심 없음(블로그)**: 숨길 수 있는 블로그는 누구나 볼 수 있는 공개 블로그뿐. 비공개·링크 공개·숨김 블로그는 없는 블로그와 같이 404로 답한다(주소를 짐작해 있는지·이름을 알아내지 못하게). 내 목록에도 공개 블로그만 보인다
  7. **좋아요 수**: 실제로 좋아요가 한 줄 들어간 요청만 수를 올리고 알림을 보낸다(동시에 눌러 숫자만 올리기 막기)
  8. **목록 쪽 번호**: 글·블로그 수보다 뒤쪽 쪽(`?page=1000000`)은 DB에 묻지 않고 빈 목록을 준다
  9. **새벽 정리 작업**
     - 알림은 5000개씩 나눠 지운다(공지 하나에 회원 수만큼 생겨 한 번에 지우면 표를 오래 잠금)
     - 닫힌 블로그 정리는 블로그 하나씩 따로 저장하고, 하나가 실패해도 나머지를 계속한다. 사진 파일 하나를 못 지워도 나머지와 기록 정리를 계속한다
     - 글 조회 기록(`post_views`)은 "같은 사람·같은 날 한 번"을 가리는 데만 쓰므로 어제보다 오래된 것을 매일 04:20에 지운다. 날짜 색인 추가(`V21`)
  10. **배포**
      - 배포할 때마다 DB를 `~/creat-blog/backups/before-deploy-*.sql.gz`로 백업하고 최근 14개(`BACKUP_KEEP`)만 남긴다. 백업이 안 되면 경고만 하고 배포는 계속한다
      - `reset_db=reset`으로 DB를 지울 때는 먼저 반드시 백업하고, 백업이 안 되면 지우지 않고 멈춘다
      - 컨테이너 로그는 20MB씩 5개까지만 둔다
  11. **PR 테스트**: PR마다 GitHub Actions에서 `./gradlew test`를 돌린다(`.github/workflows/test.yml`). 저장소 설정에서 이 검사를 필수로 지정하면 테스트가 깨진 PR은 합칠 수 없다

  - 요청 제한 카운터를 서버 두 대가 함께 쓰기: D-83(공용 저장소) 결정을 기다린다
  - 비밀번호 찾기의 이메일별 하루 실패 총량: 새 표가 필요하고, 1번으로 이미 시간당 시도 수가 크게 줄었다
  - reCAPTCHA 시험용 키로 운영 서버가 뜨지 않게 하기: 지금 운영 서버에 키가 들어 있는지 확인한 뒤에 켠다 (키가 없으면 사이트가 안 뜸)
  - 서버 밖(다른 컴퓨터·클라우드)으로 백업 옮기기, 사진을 Nginx가 바로 내보내기: 서버 설정 일
  - 관리자 로그아웃 때 토큰 무효로 하기, 링크 미리보기 썸네일 정리, 소셜 로그인 자동 연결 알림 메일
