# D-130 인증번호 이메일별 하루 총량, 소셜 자동 연결 알림, 관리자 로그아웃 무효

- 날짜: 2026-11-18
- 관련 요구사항: USR-02, USR-06, SEC-05, SEC-09, SCL-01, D-103, D-126, D-127, D-128
- 사용자 요청 (김채림, 2026-11-18): "블로그에서 보강해야 할점 알려줘봐" → "하나씩 해결하자" → "2번 제외하고 하자". 점검 5·6·7번
- 결정
  1. **인증번호 이메일별 하루 총량**: 가입·비밀번호 찾기 인증번호를 이메일 한 곳에 하루 10번(`RATE_MAIL_PER_EMAIL_PER_DAY`)까지 보낸다. 가입과 비밀번호 찾기는 따로 센다. 넘으면 `MAIL_DAILY_LIMIT`(429) "이 이메일로는 오늘 인증번호를 더 보낼 수 없습니다. 내일 다시 시도해 주세요."
     - 번호마다 5번씩 맞혀 볼 수 있어, 이전에는 1분마다 새 번호를 받아 한 계정에 시간당 약 300번 맞혀 볼 수 있었고 받는 사람은 메일 폭탄을 받았다. 이제 한 이메일에 하루 50번까지만 맞혀 볼 수 있다(100만 가지 중)
     - 비밀번호 찾기는 가입 안 된 이메일도 똑같이 세어, 답으로 가입 여부를 알 수 없게 한다
     - 서버 두 대가 같이 세도록 DB 표 `email_daily_sends`에 센다(SCL-01). 줄을 늘리고 바로 읽어 동시에 보내도 빠뜨리지 않는다. 넘은 요청은 되돌려져 숫자도 늘지 않는다
     - 날짜는 한국 날짜. 지난 날짜 줄은 새벽 4시 정리 작업이 지운다
     - IP별 요청 제한(D-83 보류)과는 따로다. 이 값은 이메일 기준이라 IP 제한 수치를 정하는 일과 겹치지 않는다
  2. **소셜 로그인 자동 연결 알림**: 구글·네이버·카카오 계정의 이메일이 기존 회원과 같아 자동으로 연결되면, 그 이메일로 "OO 계정이 연결되었습니다" 메일을 보낸다. 본인이 아니면 비밀번호를 바꾸라고 안내한다. 이미 연결된 뒤 로그인할 때와, 회원이 이메일·비밀번호를 확인하고 직접 연결할 때(D-126)는 보내지 않는다
  3. **관리자 로그아웃 때 토큰 무효**: 로그아웃하면 `admins.tokens_revoked_at`에 그 시각을 적고, 그보다 먼저 받은 관리자 토큰은 2시간이 남았어도 받지 않는다(비밀번호를 바꿨을 때와 같은 방식). 그 관리자가 다른 기기에서 열어 둔 관리자 화면도 함께 로그아웃된다
- 마이그레이션 `V22__email_daily_sends_admin_logout.sql`
- 고르지 않은 것
  - 관리자 30분 유휴 만료: 지금 2시간 만료로 두고, 필요하면 따로 정한다
  - 네이버가 돌려주는 이메일 확인 여부를 따로 검사하기: 알림 메일로 주인이 알 수 있게 하는 것으로 대신한다
