# Creat_ v1.6.0 업데이트 소식

Creat_를 **서버 두 대**로 돌리고, 새 버전으로 바꾸는 동안에도 <u>사이트가 끊기지 않는</u> **롤링 무중단 배포**를 서버에서 구성하고 확인했어요.

> 지금까지는 업데이트할 때마다 10초쯤 사이트가 안 열렸어요. 이제 <span class="hl-yellow">한 대씩 차례로 바꿔서</span> 그 사이에도 다른 한 대가 손님을 받아요.

## 업데이트할 때마다 사이트가 잠깐 멈췄어요

**무엇이 불편했나요**

새 버전을 올릴 때마다 옛 서버를 끄고 새 서버를 켜는 사이 **10초쯤 사이트가 열리지 않았어요** (502 에러). 서버가 한 대뿐이라 그 한 대가 멈추면 사이트 전체가 멈췄어요.

**원인**

앱 서버가 한 대(8340번 포트)뿐이었어요. 끄고 켜는 동안 요청을 대신 받아 줄 서버가 없었어요.

**어떻게 고쳤나요**

1. 같은 앱을 **두 대**(8340, 8341) 띄웠어요. 같은 DB·같은 사진 폴더·같은 로그인 키를 써서 어느 쪽이 받아도 결과가 같아요.
2. 앞에 있는 **Nginx(안내 데스크)** 가 요청을 두 대에 번갈아 나눠 주고, 한쪽이 대답이 없으면 다른 쪽으로 다시 보내요.
3. 새 버전으로 바꿀 때는 **한 대씩 차례로** 바꿔요 (롤링 배포). 바꾼 서버가 다시 요청을 받기 시작한 걸 확인한 뒤에 다음 서버를 바꿔요.

**얼마나 달라졌나요**

> 한 대씩 바꾸는 동안에도 모든 요청이 <span class="hl-yellow">200(정상)</span>으로 돌아왔어요. 업데이트 중 멈춤 <u>약 10초 → 0초</u>

![두 대에 번갈아 나눠 주다가, 한 대를 바꾸는 동안에는 나머지 한 대가 모두 받는 화면 (전부 200)](/img/releases/v1.6.0/rolling-ok.png)

## 확인하다 찾은 문제 두 가지

**① 처음에는 한쪽(8340)으로만 갔어요**

Nginx 일꾼(worker)이 여럿인데 각자 순서를 따로 세서, 매번 첫 번째 서버로만 보냈어요. 일꾼들이 순서를 함께 세게(`zone`) 고치니 번갈아 나눠졌어요.

![고치기 전: 10번 모두 8340](/img/releases/v1.6.0/lb-before-zone.png)

**② 바꾸는 순서가 너무 빠르면 502가 났어요**

2번 서버가 켜지자마자 1번 서버를 껐더니, Nginx가 아직 2번을 "잠깐 쉬는 중"으로 알고 있어서 **보낼 곳이 없다며 502**를 냈어요. 2번 서버가 켜진 뒤 **10초 기다렸다가** 1번을 바꾸니 502가 사라졌어요.

![고치기 전: 10초 대기 없이 바꿨을 때 502가 8번](/img/releases/v1.6.0/rolling-502.png)

> 지금은 학교 서버의 테스트용 안내 데스크로 확인한 단계예요. creat.java21.net 주소로 들어오는 요청이 두 대로 나뉘는 건 학교 Nginx에 설정이 반영된 뒤부터예요.

## 운영 메모

| 항목 | 값 |
|---|---|
| app1 | 컨테이너 `creat-blog`, `--network host`, `SERVER_PORT=8340` |
| app2 | 컨테이너 `creat-blog-2`, 같은 이미지·`secrets.env`·`runtime.env`·`data/uploads`, `SERVER_PORT=8341` |
| 검증용 LB | 컨테이너 `lbtest`(`nginx:alpine`, `--network host`, `listen 8342`), `upstream app { zone app 64k; server 127.0.0.1:8340 max_fails=1 fail_timeout=5s; server 127.0.0.1:8341 ... }`, `proxy_next_upstream error timeout http_502 http_503`, `proxy_connect_timeout 2s`, `add_header X-Upstream $upstream_addr always` |
| 학교 Nginx | `~/nginx/creat.java21.net.conf`에 `upstream creat_java21_net`(8340·8341) 넣어 둠. **reload 전**이라 실제 도메인은 아직 8340 한 대 |

### 확인 방법

```bash
# 분산: 8340·8341이 번갈아
for i in $(seq 1 10); do curl -s -o /dev/null -D - http://localhost:8342/ | grep -i x-upstream; done
# 롤링: 다른 창에서 0.5초마다 요청을 보내며 한 대씩 재시작
docker restart -t 30 creat-blog-2
until curl -fs -o /dev/null http://localhost:8341/; do sleep 2; done; sleep 10   # fail_timeout(5s)보다 길게
docker restart -t 30 creat-blog
until curl -fs -o /dev/null http://localhost:8340/; do sleep 2; done
```

### 왜 롤링인가

블루그린·카나리는 배포마다 Nginx가 가리키는 곳이나 비율을 바꾸고 reload해야 하는데, 학교 Nginx reload는 강사님만 할 수 있어요. 롤링은 upstream을 한 번 넣어 두면 배포 때 Nginx를 건드리지 않아요.

### 남은 일

- 학교 Nginx reload (upstream에 `zone creat_java21_net 64k;` 추가 권장).
- `deploy.sh` 자동 롤링(현재 배포는 `creat-blog` 한 대만 다시 띄움). 두 대일 때 소셜 로그인 중간값(OAuth2 authorization request)을 세션 대신 쿠키에 두기, 새벽 정리 작업을 한 대에서만 돌리기.

자세한 설명은 [포트·Nginx·롤링 배포 정리](docs/05-guides/포트-nginx-롤링배포.md), [CHANGELOG](CHANGELOG.md)에 있어요.
